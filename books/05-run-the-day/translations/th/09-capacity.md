# 9. ความจุ โดยไม่กุตัวเลขขึ้นมาเอง

หน้าที่ด้านความจุประจำวันของผู้จัดการศูนย์ข้อมูลถูกควบคุมโดยคำถามพื้นฐานสามข้อ:
1. คุณขายความจุตามสัญญาให้ลูกค้าไปเท่าใด?
2. ณ วินาทีนี้ มีการใช้ความจุจริงทางกายภาพไปเท่าใด?
3. จะมีความจุเหลือรอดอยู่เท่าใดหากอุปกรณ์ชิ้นที่ใหญ่ที่สุดของคุณพังลงในตอนนี้?

```
+-----------------------------------------------------------------------------+
| เพดานความซ้ำซ้อนของความจุ 2N |
| |
| 100% +----------------------------------------------------------------+ |
| | โซนอันตรายที่ห้ามใช้งาน | |
| | หากบัส A ทริป บัส B จะโอเวอร์โหลดและระบบดับมืดทันที | |
| 90% +================================================================+ |
| | โหลดสูงสุดที่ยอมให้รอดได้ (90%) | |
| | | |
| 50% + - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -+ |
| | กฎ 45%: โหลดสภาวะคงที่สูงสุดที่อนุญาต | |
| 45% +----------------------------------------------------------------+ |
| | | |
| | กรอบการทำงานที่ปลอดภัยของระบบ 2N | |
| | โหลดบัส A <= 45% | โหลดบัส B <= 45% | |
| 0 +----------------------------------------------------------------+ |
+-----------------------------------------------------------------------------+
```

หากคุณไม่สามารถตอบคำถามสามข้อนี้ได้อย่างมั่นใจในเชิงคณิตศาสตร์จากบันทึกการวัดที่ผ่านการตรวจสอบแล้ว คุณก็ไม่รู้เลยว่าการบำรุงรักษาหรือการติดตั้งเซิร์ฟเวอร์ที่เสนอมาในวันนี้ปลอดภัยหรือไม่

## คณิตศาสตร์ของความซ้ำซ้อนแบบ 2N: กฎ 45%

ความเชื่อผิดๆ ในการปฏิบัติงานที่แพร่หลายและอันตรายที่สุดในการบริหารศูนย์ข้อมูลคือความเชื่อที่ว่า ในสถาปัตยกรรมไฟฟ้าแบบสำรอง 2N แต่ละเส้นทางสามารถใช้งานได้อย่างปลอดภัยถึง **50% ของพิกัดความจุบนแผ่นป้ายชื่อ**

นี่คือกับดักทางคณิตศาสตร์ที่ก่อให้เกิดเหตุการณ์ระบบดับต่อเนื่องเป็นลูกโซ่ระดับหลายเมกะวัตต์ทั่วทั้งอุตสาหกรรม:

$$P_{\text{total}} = P_{\text{Bus A}} + P_{\text{Bus B}}$$

พิจารณาบัสบาร์ไฟฟ้า 2N ที่มีพิกัด 2000 kVA ผู้จัดการฝ่ายปฏิบัติการสังเกตเห็นว่าบัส A รับโหลด 1040 kVA (โหลด 52%) และบัส B รับโหลด 1020 kVA (โหลด 51%) ผู้จัดการสันนิษฐานว่าเนื่องจากไม่มีบัสบาร์ใดทำงานเกินพิกัด ระบบจึงยังทำงานอยู่ภายในขอบเขตความปลอดภัยอย่างสบายๆ

ทันใดนั้น หม้อแปลงต้นทางที่จ่ายไฟให้บัส A เกิดทริป
ภายในเวลาไม่กี่มิลลิวินาที พาวเวอร์ซัพพลายของเซิร์ฟเวอร์ไอทีแบบสายคู่ทั้งหมดที่ต่ออยู่กับบัส A จะถ่ายโอนโหลดไฟฟ้าไปยังบัส B

โหลดรวมในทันทีที่ตกอยู่กับบัส B จะกลายเป็น:

$$P_{\text{Bus B, transient}} = 1040\,\text{kVA} + 1020\,\text{kVA} = 2060\,\text{kVA} \quad (103\% \text{ ของพิกัดความจุ})$$

บัส B จะโอเวอร์โหลดในทันที เบรกเกอร์หลักของบัส B จะตรวจพบกระแสเกินต่อเนื่องและทริปหลังจากผ่านช่วงหน่วงเวลาสั้นๆ ทำให้ห้องเซิร์ฟเวอร์ทั้งหมดตกอยู่ในความมืดมิด ศูนย์ข้อมูลที่ออกแบบมาเพื่อให้สามารถทนทานต่อความผิดพร่องแบบ 2N สมบูรณ์แบบ กลับต้องเผชิญกับไฟฟ้าดับ 100% จากความล้มเหลวของอุปกรณ์เพียงชิ้นเดียว

เพื่อป้องกันการทริปต่อเนื่องเป็นลูกโซ่ วงจรจ่ายไฟแบบ 2N ทุกเส้นทางจะต้องปฏิบัติตาม **กฎการจ่ายโหลด 45%** อย่างเคร่งครัด:

$$P_{\text{steady-state}} \le 0.45  \times P_{\text{rated}}$$

ภายใต้กฎ 45%:
- บัส A รับโหลด ≤ 45% (900 kVA)
- บัส B รับโหลด ≤ 45% (900 kVA)
- หากบัส A ทริป บัส B ที่เหลือรอดจะรับโหลดรวม 900 + 900 = 1800 kVA (90% ของพิกัดความจุ)
- บัส B จะทำงานได้อย่างเสถียรโดยมีขอบเขตความปลอดภัยสำรองอยู่ 10% ซึ่งอยู่ต่ำกว่าเกณฑ์การทริปของระบบความร้อน-แม่เหล็ก ทำให้ช่างเทคนิคมีเวลาจัดการกับสถานการณ์ได้อย่างปลอดภัย

ผู้จัดการเวรคนใดที่ยินยอมให้บัสบาร์ไฟฟ้า 2N ใช้งานในสภาวะคงที่เกิน 45% ถือว่าได้ทำลายความซ้ำซ้อนของศูนย์ข้อมูลลงแล้ว และกำลังเดินระบบอยู่ในสภาวะที่มีความเสี่ยงสูงโดยไม่ได้รับการรับรอง

## ความจุทางชลศาสตร์ของลูปหล่อเย็นทุติยภูมิ

ในห้องเซิร์ฟเวอร์ AI ที่ระบายความร้อนด้วยของเหลวซึ่งติดตั้งแร็คประมวลผลความหนาแน่นสูง (เช่น สถาปัตยกรรม NVIDIA NVL72 ที่ใช้พลังงานสูงถึง 132 kW ต่อแร็ค) การจัดการความจุทางชลศาสตร์มีความสำคัญไม่ยิ่งหย่อนไปกว่าความจุทางไฟฟ้า:

```
+-----------------------------------------------------------------------------+
| เพดานความจุทางชลศาสตร์ของ CDU |
| |
| พารามิเตอร์ ขีดจำกัดตามการออกแบบ ขีดจำกัดความซ้ำซ้อนปฏิบัติการ|
| ------------------ ------------------------ --------------------------- |
| การระบายความร้อนรวม 1200 kW ต่อ CDU <= 1000 kW (83% ของ PHE) |
| อัตราการไหลทุติยภูมิ 1440 LPM (24 LPS) <= 1200 LPM (ปั๊มเดี่ยว N) |
| อุณหภูมิน้ำจ่าย 25.0°C - 32.0°C (W3/W4) <= 30.0°C (ที่อุณหภูมิภายนอกสูงสุด)|
| โครงสร้างปั๊ม N+1 ปั๊มคู่แบบ VFD รัน 1 ปั๊ม / สแตนด์บาย 1 ปั๊ม |
| ความดันในลูป 0.15 - 0.90 MPa ความดันสูญเสีย Delta-P < 1.0 bar|
+-----------------------------------------------------------------------------+
```

เมื่อต้องประเมินคำขอของลูกค้าในการติดตั้งแร็คระบายความร้อนด้วยของเหลวความหนาแน่นสูงเพิ่มเติม ผู้จัดการเวรจะต้องประเมินข้อจำกัดทางชลศาสตร์:
1. **ความพร้อมของอัตราการไหลรวม**: ตรวจสอบว่าปั๊มทุติยภูมิสามารถจ่ายอัตราการไหลเชิงปริมาตร (q_v) ตามที่กำหนดเพื่อรักษาการไหลแบบปั่นป่วนในโคลด์เพลตได้หรือไม่:

$$q_v = \frac{Q}{\rho \cdot c_p \cdot \Delta T}$$

โดยที่:
- Q คือการกระจายความร้อนทั้งหมด ( kW)
- $
- ρ คือความหนาแน่นของโพรพิลีนไกลคอล 25% (1026\, kg/m^3ที่30°C$)
- c_p คือความจุความร้อนจำเพาะ (3.92 kJ/( kg· K))
- ΔT คืออุณหภูมิของเหลวที่เพิ่มขึ้นข้ามแมนิโฟลด์แร็ค (โดยทั่วไปคือ 10.0 K)

2. **ความไม่สมดุลทางชลศาสตร์และการขาดแคลนการไหลแบบต่อตรง**: เมื่อมีการต่อแร็คเพิ่มเติมเข้ากับแมนิโฟลด์จ่ายทุติยภูมิ ความดันสูญเสียจากแรงเสียดทาน (ΔP_f) จะเพิ่มขึ้นเป็นสัดส่วนกำลังสองตามความเร็วการไหล (v):

$$\Delta P_f = f \cdot \frac{L}{D} \cdot \frac{\rho v^2}{2}$$

หากแมนิโฟลด์ถูกเดินท่อแบบไหลกลับโดยตรง (Direct-return) แทนที่จะเป็นแบบลูปไหลกลับย้อนทาง (Reverse-return / Tichelmann) การเพิ่มโหลดที่ปลายแถวจะทำให้แร็คตัวท้ายๆ ขาดแคลนของเหลวหล่อเย็น ส่งผลให้ GPU เกิดการลดความเร็วเพื่อระบายความร้อน (Thermal throttling) ในทันที

อย่าอนุมัติการเพิ่มโหลดของเหลวโดยอาศัยเพียงคำรับรองทางวาจาจากลูกค้าว่า "ปั๊มดูเหมือนจะใหญ่พอ" จงเรียกดูผลการจำลองการไหลทางชลศาสตร์และการคำนวณความดันตกที่ผ่านการรับรองก่อนออกใบอนุญาตเชื่อมต่อเสมอ

## ความเชื่อผิดๆ เรื่องการ "ลองจ่ายไฟดู"

เมื่อลูกค้าหรือทีมติดตั้งโครงการขออนุญาตจ่ายไฟให้แร็คเซิร์ฟเวอร์เพิ่มเติมซึ่งเกินกว่ากรอบความจุที่คำนวณไว้ พวกเขามักจะเสนอว่า:
> *"เรามาลองจ่ายไฟให้แร็คแล้วคอยดูมิเตอร์สักยี่สิบนาทีกันดีกว่า เพื่อดูว่าเบรกเกอร์จะทนไหวไหม"*

นี่เทียบเท่ากับการทดสอบความหนาของแผ่นน้ำแข็งด้วยการขับรถบรรทุกสามสิบตันขึ้นไปวิ่งบนนั้น

การจ่ายไฟให้อุปกรณ์ "เพื่อดูว่าจะทนไหวไหม":
- ทำให้บัสบาร์ไฟฟ้าและหม้อแปลงต้องเจอกับกระแสกระชากมหาศาลและการช็อกทางความร้อน
- เสี่ยงต่อการทำให้รีเลย์ป้องกันต้นทางทริป ส่งผลให้ลูกค้าข้างเคียงที่กำลังใช้งานอยู่เกิดไฟดับในทันที
- นำการพนันที่ประมาทเลินเล่อเข้ามาแทนที่วิศวกรรมคณิตศาสตร์ที่เข้มงวด

หากคำขอติดตั้งโหลดเกินกว่าส่วนแบ่งตามสัญญาหรือเกินเพดานความซ้ำซ้อน 45% ผู้จัดการเวรจะต้องปฏิเสธการอนุญาตทันที ระงับการจ่ายไฟ ลูกค้าจะต้องยื่นผลการศึกษาทางวิศวกรรมอย่างเป็นทางการและเจรจาแก้ไขสัญญาให้เรียบร้อยก่อนที่จะมีการสับสวิตช์เบรกเกอร์ตัวถัดไปขึ้น

## การตัดสินใจที่ต้องบันทึก

- ความจุตามสัญญาที่ขายไป โดยระบุข้อสัญญาของลูกค้าและหมายเลขแร็ค
- โหลดไฟฟ้าจริงที่บันทึกได้ในแต่ละบัสบาร์ พร้อมยืนยันการปฏิบัติตามกฎความซ้ำซ้อน 45%
- อัตราการไหลของลูปทุติยภูมิทางชลศาสตร์ อุณหภูมิน้ำจ่าย และความดันต่างที่บันทึกต่อ CDU แต่ละตัว
- ความจุที่เหลือรอดหลังจากความล้มเหลวของอุปกรณ์เดี่ยวชิ้นที่ร้ายแรงที่สุด: ได้รับการยืนยันจากผลการศึกษาทางวิศวกรรม หรือบันทึกว่าไม่ทราบแน่ชัด
- คำขอจ่ายไฟเกินความจุที่ปลอดภัยต้องได้รับการปฏิเสธเป็นลายลักษณ์อักษร; ห้ามมีการจ่ายไฟ "เพื่อทดลองดู" เด็ดขาด
