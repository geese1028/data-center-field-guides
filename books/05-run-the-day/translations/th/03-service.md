# 3. บริการที่คุณขาย

ลูกค้าไม่ได้ซื้อถังน้ำมันดีเซล แผ่นแลกเปลี่ยนความร้อนไทเทเนียม หรือความทุ่มเทส่วนตัวของคุณ สิ่งที่ลูกค้าซื้อคือ SLA: สัญญาการให้บริการที่ระบุไว้อย่างชัดเจนทางคณิตศาสตร์ซึ่งรับประกันความพร้อมใช้งานของระบบไฟฟ้า การส่งมอบอุณหภูมิ และเวลาในการแจ้งเตือนอุบัติการณ์ หากคุณไม่สามารถอ้างอิงข้อสัญญาที่แน่นอนในสัญญาการให้บริการหลักได้ แสดงว่าคุณกำลังทำงานอยู่บนพื้นฐานของการบอกเล่าต่อๆ กันมา

**ตารางขอบเขตการให้บริการ**

| พารามิเตอร์ตามสัญญา ขีดจ | ำกัดที่รับประกัน แหล่งข้อม | ูลการวัด |
| :--- | :--- | :--- |
| ความพร้อมใช้งานของไฟฟ้า | 99.999% (Five Nines) มิเตอ | ร์คิดเงินของ PDU |
| อุณหภูมิน้ำจ่ายทุติยภูมิ | 25.0°C ถึง 32.0°C (W3/W4) | เซนเซอร์ RTD จ่าย CDU |
| น้ำเย็นปฐมภูมิ 12.0°C ถึ | ง 18.0°C อัตราไหล/อุณหภูมิ | FWS |
| อุณหภูมิอากาศ (หน้าแร็ค) | 18.0°C ถึง 27.0°C (ASHRAE | ) เซนเซอร์ทางเดินเย็น |
| เวลาแจ้งเตือนอุบัติการณ์ | <= 15 นาทีจากตรวจพบ พอร์ท | ัลลูกค้า & โทรศัพท์ |

## ขีดจำกัดบริการตามสัญญา vs. ขอบเขตความปลอดภัยทางวิศวกรรม

การบริหารศูนย์ข้อมูลจำเป็นต้องแยกแยะความแตกต่างระหว่างขอบเขตสามประการนี้ให้ชัดเจน:
1. **ค่าที่ตั้งไว้ตามการออกแบบ (Design Setpoints)**: สภาวะการทำงานที่เหมาะสมที่สุดซึ่งตั้งไว้ในระบบควบคุม (เช่น น้ำจ่ายทุติยภูมิของ CDU ที่ 28.0°C อากาศในทางเดินเย็นที่ 22.0°C)
2. **ขีดจำกัดการเตือนภัยในการปฏิบัติการ (Operational Alarm Limits)**: เกณฑ์ภายในของศูนย์ข้อมูลที่เตือนให้ช่างเทคนิคดำเนินการแก้ไขก่อนที่จะเกิดผลกระทบต่อลูกค้า (เช่น น้ำจ่ายทุติยภูมิสูงถึง 30.5°C กระตุ้นให้ปั๊มสำรองเริ่มทำงานหรือชิลเลอร์เพิ่มสเตจ)
3. **ขีดจำกัดการละเมิดสัญญา (Contractual Breach Limits)**: ขอบเขตทางกฎหมายที่กำหนดไว้ใน SLA ของลูกค้าซึ่งจะส่งผลให้ถูกปรับเงินชดเชยและได้รับหนังสือแจ้งเตือนการผิดสัญญา (เช่น น้ำจ่ายทุติยภูมิเกิน 32.0°C ติดต่อกันนาน > 5 นาที หรืออากาศเข้าแร็คเกิน 27.0°C)

อย่าปล่อยให้ตัวแทนฝ่ายพาณิชย์ของลูกค้าปฏิบัติต่อสัญญาณเตือนภายในว่าเป็นเหตุละเมิดสัญญา ในทางกลับกัน อย่าให้ทีมงานในกะของคุณเพิกเฉยต่ออุณหภูมิที่พุ่งเกินเกณฑ์ SLA เพียงเพราะ "มันพุ่งขึ้นแค่สามนาทีเท่านั้น" หากสัญญากำหนดให้วัดการเบี่ยงเบนด้วยค่าเฉลี่ยเคลื่อนที่ 60 วินาที การพุ่งขึ้นสามนาทีก็คือการละเมิดสัญญา จดบันทึกมันลงไป

## สมการความพร้อมใช้งานของระบบ

ความพร้อมใช้งานของศูนย์ข้อมูล (A) คำนวณได้ดังนี้:

$$A = \frac{\text{เวลาทั้งหมดในรอบการคิด (นาที)} - \text{เวลาที่ระบบหยุดทำงาน (นาที)}}{\text{เวลาทั้งหมดในรอบการคิด (นาที)}}  \times 100\%$$

ในสัญญาการเช่าพื้นที่ศูนย์ข้อมูลและสัญญาไฮเปอร์สเกลสมัยใหม่ "เวลาที่ระบบหยุดทำงาน" (Outage Minutes) ถูกกำหนดไว้อย่างแม่นยำมากทางกฎหมาย:
- การหยุดทำงานจะต้องสูญเสียไฟฟ้าทั้งสาย A และ B ของแร็ค 2N หรือไม่ หรือการสูญเสียความซ้ำซ้อนเพียงสายเดียวถือเป็นการหยุดทำงานบางส่วนหรือไม่?
- หากเซิร์ฟเวอร์ของลูกค้ายังคงทำงานต่อไปได้บนสาย B ขณะที่สาย A ดับ นาฬิกา SLA จะเริ่มเดินหรือไม่?
- หาก CDU ระบบหล่อเย็นลดรูปจากการทำงานของปั๊มคู่ N+1 เหลือปั๊มเดี่ยวโดยไม่มีการลดทอนประสิทธิภาพทางความร้อน ถือว่าเกิดการหยุดทำงานหรือไม่?

ผู้จัดการเวรต้องทราบคำตอบตามสัญญาสำหรับคำถามเหล่านี้ล่วงหน้าก่อนที่เหตุการณ์จะเกิดขึ้น ในระหว่างเกิดอุบัติการณ์จริง ไม่มีเวลาให้คุณไปปรึกษาที่ปรึกษากฎหมายภายนอก

## นาฬิกาแจ้งเตือนอุบัติการณ์

เมื่อความผิดปกติของโครงสร้างพื้นฐานก้าวข้ามเกณฑ์ SLA นาฬิกาจะเริ่มเดินทันที:

$$\Delta t_{\text{notice}} = t_{\text{sent}} - t_{\text{detect}} \le T_{\text{contractual}}$$

SLA ของไฮเปอร์สเกลส่วนใหญ่กำหนดให้ต้องส่งหนังสือแจ้งเตือนอุบัติการณ์อย่างเป็นทางการภายใน **15 นาที** นับจากการตรวจพบครั้งแรก (T_contractual ≤ 15 นาที)

| **กรอบเวลาแจ้งเตือน 15 นาที** |
| :--- |
| T = 00:00 สัญญาณเตือนบน BMS/EPMS ดังขึ้น; ตรวจพบการทริป |
| T + 05:00 ผู้จัดการเวรยืนยันเหตุการณ์; ควบคุมเข้าสู่สภาวะปลอดภัย |
| T + 10:00 ร่างข้อความแจ้งเตือน: อาการ, เวลา, ห้องที่ได้รับผลกระทบ |
| T + 14:00 ส่งข้อความแจ้งเตือนไปยังผู้ประสานงานเทคนิคของลูกค้า |
| T + 15:00 สิ้นสุดเส้นตายการแจ้งเตือนตามข้อตกลง SLA |

ความล้มเหลวที่พบบ่อยในหมู่ผู้จัดการมือใหม่คือการชะลอการแจ้งเตือนลูกค้าในเบื้องต้นเพื่อรอให้ช่างเทคนิคหาสาเหตุที่แท้จริงให้พบก่อน นี่คือหายนะตามสัญญา ลูกค้าอาจให้อภัยหม้อแปลงทริปที่สามารถควบคุมเข้าสู่สภาวะปลอดภัยได้ภายในไม่กี่นาที แต่พวกเขาจะไม่ให้อภัยอย่างเด็ดขาดหากพบว่าเซิร์ฟเวอร์ของพวกเขาดับจากระบบมอนิเตอร์ของตัวเองในขณะที่ผู้จัดการศูนย์ข้อมูลเงียบหายไปนานถึงสี่สิบนาที

ส่งการแจ้งเตือนในนาทีที่ 12 ระบุข้อเท็จจริงที่สังเกตได้: เวลาที่เกิดเหตุ บัสไฟฟ้าหรือลูปหล่อเย็นที่ได้รับผลกระทบ สถานะปัจจุบันของระบบสำรองฉุกเฉิน และเวลาที่จะอัปเดตข้อมูลครั้งต่อไป อย่าใส่สมมติฐานเกี่ยวกับสาเหตุลงไปในข้อความเด็ดขาด

## สิ่งที่คุณต้องไม่รายงานว่าเป็นข้อผูกพัน

จงวัดเฉพาะสิ่งที่สัญญาระบุไว้เท่านั้น การคำนวณตัวชี้วัดประสิทธิภาพการทำงานภายใน—เช่น ค่าประสิทธิภาพการใช้พลังงาน (PUE), ค่าประสิทธิภาพการปล่อยคาร์บอน (CUE) หรือค่าประสิทธิภาพการใช้น้ำ (WUE) แบบเรียลไทม์—มีความสำคัญต่องานวิศวกรรมและการรายงานความยั่งยืนขององค์กร อย่างไรก็ตาม อย่าได้คัดลอกการคำนวณ PUE ภายในใส่ลงในใบรับรองการส่งมอบ SLA ประจำวัน เว้นแต่สัญญาจะระบุไว้อย่างชัดเจนว่า PUE เป็นพารามิเตอร์ SLA ที่ใช้ในการเรียกเก็บเงิน

หากอัตราส่วนประสิทธิภาพไม่ได้เป็นส่วนหนึ่งของสัญญาเชิงพาณิชย์ การนำไปรายงานในบันทึกประจำวันของลูกค้าจะเปลี่ยนเป้าหมายทางวิศวกรรมภายในให้กลายเป็นเป้าหมายภายนอกที่ลูกค้าจะนำมาใช้โต้แย้งใบแจ้งหนี้ แยกบันทึกการส่งมอบงานตามสัญญาออกจากข้อมูลวิเคราะห์ทางวิศวกรรมภายในอย่างเคร่งครัด

## การตัดสินใจที่ต้องบันทึก

- ชื่อสัญญาหลัก ฉบับแก้ไขเพิ่มเติม และข้อสัญญาที่ควบคุมการให้บริการของวันนี้
- หมายเลขประจำตัวมิเตอร์เทเลเมทรีและแหล่งเวลาอ้างอิงที่ใช้ในการบันทึกเวลาตามสัญญา
- กรอบเวลาการแจ้งเตือนตามสัญญา (T_contractual) ในหน่วยนาที
- การเบี่ยงเบน SLA ใดๆ ที่สังเกตพบในระหว่างกะ พร้อมบันทึกเวลาที่แม่นยำระดับไมโครวินาทีจากเครื่องบันทึกเหตุการณ์ต่อเนื่อง (SOE)

## เส้นแบ่งขอบเขตความรับผิดชอบทางกายภาพและโปรโตคอลการตรวจสอบกะเชิงปริมาณ

ผู้จัดการกะปฏิบัติการต้องรักษาจุดแบ่งขอบเขตความรับผิดชอบ (`DEMARC`) ทั้ง 4 วงแหวนของศูนย์ข้อมูล (Ring 1: ระบบรับไฟฟ้าและรั้วโครงการ, Ring 2: ห้องเครื่องหลักและหม้อแปลง, Ring 3: ระบบจ่ายในห้องเซิร์ฟเวอร์และ CDU ทุติยภูมิ, Ring 4: ภายในแร็คของลูกค้า) และบันทึกเกณฑ์วัดผลเชิงปริมาณต่อไปนี้ลงในแผ่นงานประจำวัน (Day Sheet):

| หมวดการตรวจสอบกะ | พารามิเตอร์ที่ตรวจวัด | ขอบเขตการทำงานปกติ | เกณฑ์สั่งหยุดงานทันที (Stop Work) / ปฏิเสธ |
| :--- | :--- | :--- | :--- |
| **เพดานโหลดระบบไฟฟ้าสำรอง 2N** | โหลดปกติบนบัส A / บัส B ($P_{\text{bus}} / P_{\text{rated}}$) | $\le 45.0\%$ (เมื่อเสีย 1 ฝั่ง โหลดรวม $\le 90.0\%$) | ปฏิเสธการจ่ายไฟแร็คใหม่ทันทีหากโหลดเกิน $45.0\%$ |
| **ไฮดรอลิกและเคมีของ CDU ทุติยภูมิ** | ความดันจ่าย $P_{\text{sup}}$, อุณหภูมิเข้าใกล้ $\Delta T_{\text{PHE}}$, ความเข้มข้น PG | $0.15\sim 0.90\,\text{MPa}$, $\Delta T_{\text{PHE}} \le 8.0\,\text{K}$, PG $25.0\% \pm 1.0\%$ | ความดันตกคร่อม $> 1.0\,\text{bar}$, ค่าการนำไฟฟ้า $> 10\,\mu\text{S/cm}$ หรือพบหยดน้ำ |
| **ใบอนุญาตทำงาน (PTW) และ LOTO** | การล็อกกุญแจ LOTO, การคายประจุ และวาล์วบายพาส | มีผู้ควบคุมของศูนย์ข้อมูลประกบ 100% และปิดงานก่อนหมดเวลา | หยุดงานทันทีหากทำนอกเหนือขั้นตอน MOP ที่อนุมัติ |
| **นาฬิกาเหตุขัดข้องและการแจ้ง SLA** | เวลาตรวจพบ ($T_0$), การเข้าสู่สภาวะปลอดภัย EOP, การแจ้งลูกค้า | P1: แจ้งข้อเท็จจริงภายใน $\le 15\,\text{นาที}$ | ห้ามใส่ข้อสันนิษฐานหรือการคาดเดาลงในใบแจ้งเหตุฉบับแรก |

$$\gamma(T, \text{RH}) = \frac{a \cdot T}{b + T} + \ln\left(\frac{\text{RH}}{100}\right), \qquad T_{\text{dp}} = \frac{b \cdot \gamma(T, \text{RH})}{a - \gamma(T, \text{RH})}$$

$$\text{SLA Availability (\%)} = \left( 1 - \frac{\sum t_{\text{outage\_minutes}}}{T_{\text{month\_minutes}}} \right) \times 100\%$$
