영어판을 AI 보조로 번역한 것이다.

# 3. 판매한 서비스

고객은 당신의 디젤 연료 탱크, 티타늄 판형 열교환기, 혹은 당신의 개인적인 헌신을 사는 것이 아니다. 고객이 사는 것은 SLA(서비스 수준 계약)이다. 즉, 전력 가용성, 열 공급 한계, 장애 통보 시간을 수학적으로 정의한 계약을 사는 것이다. 마스터 서비스 계약서의 정확한 조항을 인용할 수 없다면 당신의 운영은 풍문에 의존하고 있는 것이다.

**서비스 경계 매트릭스**

| 계약 매개변수 보증 한계값 측정 소스 |  |  |
| :--- | :--- | :--- |
| 교류 전력 가용성 99.999% (파이브 나 | 인) PDU 과금 전력량계 |  |
| 2차측 공급 액체 온도 25.0°C ~ 32 | .0°C (W3/W4) CDU TCS 공급단 R | TD 센서 |
| 1차측 냉수 온도 12.0°C ~ 18.0° | C FWS 헤더 유량 및 온도 |  |
| 공기 온도 (랙 흡기) 18.0°C ~ 27 | .0°C (ASHRAE) 콜드 아일 센서군 (3 | 단) |
| 장애 통보 제한 시간 인지 후 15분 이내 | 고객 포털 및 유선 통보 |  |

## 계약상 서비스 한계 vs. 엔지니어링 마진

데이터센터 운영에서는 다음 세 가지 경계를 명확히 구분해야 한다:
1. **설계 설정값(Design Setpoints)**: 제어 로직에 프로그래밍된 최적 운전 조건(예: CDU 2차측 공급 온도 28.0°C, 콜드 아일 공기 온도 22.0°C).
2. **운영 경보 한계(Operational Alarm Limits)**: 고객 영향이 발생하기 전에 기술자가 시정 조치를 취하도록 알리는 내부 임계값(예: 2차측 공급 온도가 30.5°C에 도달하여 대기 펌프 기동이나 냉동기 추가 가동을 촉구).
3. **계약 위반 한계(Contractual Breach Limits)**: 서비스 크레딧 위약금과 계약 불이행 통보를 유발하는 고객 SLA상의 법적 경계(예: 2차측 공급 온도가 5분 연속 32.0°C를 초과하거나, 랙 흡기 온도가 27.0°C를 초과).

고객사의 영업 대표가 내부 운영 경보를 계약 위반으로 몰아세우도록 내버려두지 마라. 반대로, 현장 운영팀이 SLA 임계값을 벗어난 온도 상승을 "단 3분간 튀었을 뿐"이라는 이유로 묵살해서도 안 된다. 계약서가 60초 이동 평균으로 일탈을 측정하도록 규정하고 있다면 3분간의 스파이크는 명백한 SLA 위반이다. 정확히 기록하라.

## 가용성 계산 공식

데이터센터의 가용성(A)은 다음과 같이 계산된다:

$$A = \frac{\text{총 기간(분)} - \text{장애 중단 시간(분)}}{\text{총 기간(분)}}  \times 100\%$$

최신 멀티 테넌트 코로케이션 및 하이퍼스케일 전용 계약에서 "장애 중단 시간(Outage Minutes)"은 극도로 엄격한 법적 정의를 갖는다:
- 2N 랙의 A 전원과 B 전원이 모두 끊겨야만 중단인가, 아니면 단일 전원선 상실(이중화 상실)도 부분 중단으로 간주하는가?
- 고객 서버가 A 전원 상실 시 B 전원으로 정상 가동을 유지한다면 SLA 장애 시계가 흘러가는가?
- 액체 냉각 CDU가 이중 펌프(N+1)에서 단일 펌프 운전으로 축퇴되었으나 열적 디레이팅이 발생하지 않았다면 장애 중단이 발생한 것인가?

당직 관리자는 사고가 발생하기 전에 이러한 질문에 대한 계약상의 답을 알고 있어야 한다. 실시간 장애 상황에서는 법무팀에 자문을 구할 시간이 없다.

## 통보 시한 시계 (Notice Period Clock)

설비 이상이 SLA 임계값을 넘어선 순간, 시계는 즉시 작동하기 시작한다:

$$\Delta t_{\text{notice}} = t_{\text{sent}} - t_{\text{detect}} \le T_{\text{contractual}}$$

대부분의 하이퍼스케일 SLA는 최초 감지 후 **15분 이내**(T_contractual ≤ 15 min)에 공식 장애 통보를 요구한다.

| **15분 통보 윈도우** |
| :--- |
| T = 00:00 BMS/EPMS 경보 발생, 설비 트립 감지 |
| T + 05:00 당직 관리자가 사안 확인, 안전 상태로 격리 명령 |
| T + 10:00 1차 장애 통보문 작성: 현상, 발생 시각, 영향 구역 |
| T + 14:00 고객사 기술 담당자에게 통보 발송 |
| T + 15:00 계약상 SLA 통보 시한 만료 |

초임 운영 관리자가 저지르는 가장 흔한 실수는 기술자들이 근본 원인을 조사하는 동안 고객 통보를 지연시키는 것이다. 이는 계약상 참사다. 고객은 몇 분 만에 안전 상태로 수습된 변압기 트립은 용인할 수 있어도, 자체 모니터링을 통해 서버 다운을 감지하고 40분 동안 데이터센터 관리자가 침묵했던 것은 결코 용서하지 않는다.

12분째에 통보를 발송하라. 확인된 물리적 사실만 기록하라: 이벤트 발생 타임스탬프, 영향을 받은 전력 모선 또는 냉각 루프, 비상 백업 시스템의 현재 상태, 다음 상태 업데이트 예정 시각이다. 원인에 대한 추측은 통보문에서 완전히 배제하라.

## 약속하지 않은 수치를 보고하지 마라

계약서에 명시된 항목만 측정하고 보고하라. 실시간 PUE(전력 사용 효율), CUE(탄소 사용 효율), WUE(수자원 사용 효율)와 같은 내부 운영 지표를 산출하는 것은 설비 개선과 지속가능성 보고를 위해 필수적이다. 그러나 계약서에서 PUE를 과금 조건이나 SLA 항목으로 명시하지 않았다면 일일 SLA 리포트에 내부 PUE 수치를 붙여넣지 마라.

계약 외 효율 비율을 일일 공식 로그에 기재하면 내부의 기술적 목표가 고객이 청구서를 문제 삼는 외부 공격의 표적으로 변질된다. 계약상 이행 로그와 내부 엔지니어링 분석 데이터를 철저히 분리하라.

## 기록할 결정

- 오늘의 서비스를 규정하는 마스터 계약서의 정확한 명칭, 수정 번호 및 조항.
- 계약상 시간 측정에 사용된 공인 텔레메트리 미터 ID 및 타임 서버 소스.
- 분 단위로 표기된 계약상 통보 허용 시간(T_contractual).
- 교대 중 관찰된 모든 SLA 일탈 내역 (사건기록장치 SOE의 마이크로초 단위 타임스탬프 포함).

## 물리적 책임 분계(Demarcation) 및 정량적 교대 감사 프로토콜

교대 운영 관리자는 설비의 물리적 경계(Ring 1: 수전·외곽, Ring 2: 중앙 열원·특고압 변전, Ring 3: 홀 배전·2차 CDU, Ring 4: 고객 랙 내부)에서 책임 분계점(`DEMARC`)을 엄격히 유지하고, 다음의 정량적 감사 기준을 일일 시트(Day Sheet)에 기록해야 한다.

| 교대 감사 영역 | 감시·계측 파라미터 | 정상 운영 엔벨로프 | 즉시 개입·작업 중지(Stop Work) 임계값 |
| :--- | :--- | :--- | :--- |
| **2N 수배전 계통 부하율 상한** | 버스 A / 버스 B 정상 부하율 ($P_{\text{bus}} / P_{\text{rated}}$) | $\le 45.0\%$ (단일 계통 상실 시 $\le 90.0\%$) | $> 45.0\%$ 상태에서 신규 랙 통전 요청 즉시 거부 |
| **2차 냉각 루프(CDU) 수리·화학** | 공급 압력 $P_{\text{sup}}$, 접근 온도 $\Delta T_{\text{PHE}}$, PG 농도 | $0.15\sim 0.90\,\text{MPa}$, $\Delta T_{\text{PHE}} \le 8.0\,\text{K}$, PG $25.0\% \pm 1.0\%$ | 차압 $> 1.0\,\text{bar}$, 전도도 $> 10\,\mu\text{S/cm}$ 또는 커플러 누수 |
| **작업 허가(PTW) 및 제로 에너지 검증** | LOTO 시건, 잔류 전하 방전, 바이패스 밸브 폐쇄 확인 | 100% 현장 호스트 동행·만료 시각 전 완전 복구 | 승인된 MOP 이탈 또는 '겸사겸사 작업' 즉시 중지 |
| **인시던트 시계 및 SLA 통지** | 이벤트 감지($T_0$), EOP 안전 상태 확립, 고객 1차 통지 | P1: $T_0 + 15\,\text{min}$ 이내 물리적 사실만 통지 | 미확인 추측(가설)의 통지문 포함 절대 금지 |

$$\gamma(T, \text{RH}) = \frac{a \cdot T}{b + T} + \ln\left(\frac{\text{RH}}{100}\right), \qquad T_{\text{dp}} = \frac{b \cdot \gamma(T, \text{RH})}{a - \gamma(T, \text{RH})}$$

$$\text{SLA Availability (\%)} = \left( 1 - \frac{\sum t_{\text{outage\_minutes}}}{T_{\text{month\_minutes}}} \right) \times 100\%$$
