영어판을 AI 보조로 번역한 것이다.

# 5. 변경

데이터센터의 파국적인 대정전 참사는 대부분 낙뢰나 지진, 또는 제조사 부품 결함 때문에 일어나지 않는다. 대부분의 파국적 정전은 "일상적인 정기 유지보수"로 안이하게 분류된 변경 작업 때문에 일어난다.

```
+-----------------------------------------------------------------------------+
| 변경 실행 라이프사이클 |
| |
| [T - 72h] 엔지니어링 사전 검토: 위험도 평가, 단일장애점(SPOF) 감사 |
| | |
| [T - 24h] 변경자문위원회 (CAB) 승인: 서면 위험 인수 |
| | |
| [T - 02h] 작업 전 검증: 예비 플랜트가 100% 정상이고 경보가 없음을 확인 |
| | |
| [T = 00h] 유지보수 윈도우 개시: 제어실 현황판에 비정상 축퇴 상태 게시 |
| | |
| [T + 실행] 2인 1조 원칙에 입각한 MOP 단계별 실행 |
| | |
| [T + 검증] 실부하 기능 검증: 텔레메트리로 정상 운전 입증 |
| | |
| [T + 완료] 변경 후 서명 승인: 비정상 상태 해제, 인수인계 로그 갱신 |
+-----------------------------------------------------------------------------+
```

## 무엇이 변경에 해당하는가

변경이란 다음 중 어느 하나라도 바꾸는 모든 물리적, 전기적, 기계적, 논리적 행위를 말한다:
- 과도 상태에서 중요 인프라가 어떻게 고장 나는가(고장 모드).
- 기술자가 플랜트를 어떻게 감시하고 조작하고 제어하는가.
- 고객에게 제공되는 이중화, 용량, 또는 공급 경로 구성.

표시용 LED 램프를 동일한 부품으로 교체하는 것은 전기적 격리가 필요 없고 제어 모선 단락 위험이 없는 한 "유지보수"이다. 그러나 트립 곡선이 다른 차단기로 교체하거나, 인버터의 가감속 램프 속도를 바꾸거나, 빌딩 관리 시스템의 PID 루프 제어 매개변수를 수정하거나, CDU 2차 루프 온도 설정값을 단 0.5 K 조정하는 것은 모두 "변경"이다.

서버 부하를 전기 A 모선에서 B 모선으로 넘기는 작업은 비록 20분간일지라도 중대한 변경이다. A 모선이 분리되어 있는 동안 B 모선에서 예상치 못한 과도 서지가 발생하면 데이터센터 전체가 셧다운된다. 어떤 운영 행위가 유지보수인지 변경인지 논쟁이 생긴다면 즉시 "변경"으로 분류하라.

## 변경자문위원회(CAB)와 위험 인수

모든 변경 작업은 실행 전에 변경자문위원회(Change Advisory Board: CAB)의 공식 승인을 거쳐야 한다.

CAB 제출 문서에는 다음이 명시되어야 한다:
1. **운영상의 정당성**: 왜 이 변경이 수행되어야 하는가. "외주 엔지니어가 다른 일로 마침 현장에 와 있어서"는 결코 정당한 사유가 될 수 없다. 기록된 결함의 해결, 계약된 증설 수용, 또는 식별된 안전 취약점 완화만이 유효한 사유다.
2. **운영 위험도 등급**:
 - **1등급 (핵심)**: 실운영 IT 부하를 공급하는 활성 전력 배전이나 1차 냉각 루프를 건드리는 침습적 작업. 운영 총괄 디렉터의 서명과 고객 사전 통보가 필수.
 - **2등급 (주요)**: 이중화(N+1) 설비 작업으로, 작업 윈도우 중 가동 설비가 고장 날 경우 고객 영향이 발생하는 작업.
 - **3등급 (경미)**: 보조 설비에 대한 비침습적 작업으로, 물리적·전기적 격리를 통해 실운영 영향이 완벽히 배제된 작업.
3. **위험 인수자(The Risk Acceptor)**: 변경에 수반되는 위험을 서면으로 인수할 계약적·재무적 권한을 가진 상급 관리자의 성명. 토크 렌치를 쥐고 있는 현장 기술자는 위험 인수자가 아니다. 지정된 위험 인수자와 연락이 닿지 않는다면 유지보수 윈도우를 열지 마라.

## 비정상 운전 상태(Abnormal State) 현황판

유지보수 윈도우 동안 플랜트는 임시적인 **비정상 운전 상태(Abnormal Operating State)**로 진입한다.

이 비정상 상태의 내용은 다음과 같이 명확히 표시되어야 한다:
- 중앙 제어실 화이트보드에 굵고 선명하게 기재.
- 모든 운영자 워크스테이션의 BMS 화면 상단에 디지털 경고 배너로 표시.
- 교대 인수인계 로그에 명시적으로 기록.

```
+-------------------------------------------------------------------------+
| 중앙 제어실 비정상 상태 현황판 |
| |
| [현재 활성 결함] 냉동기 CH-03 응축기 오버홀을 위해 격리 중 |
| [잔여 이중화] 총 4대 중 3대 운전 중; 현재 이중화 = N+0 (이중화 상실)|
| [잠재적 위험] CH-01 또는 CH-02 트립 시 자동 부하 차단 발생 |
| [작업 윈도우] 2026-10-14 10:00 ~ 14:00 UTC | 위험 인수자: J. Vance |
| [복구 마감시한] 13:00 UTC (이 시점까지 조립 안 되면 즉시 중단 및 복구)|
+-------------------------------------------------------------------------+
```

물리적으로 볼트를 다 조였다고 해서 제어실 현황판과 로그에서 비정상 상태를 공식 해제하지 않고 방치하는 것은 치명적인 운영 위험이다. 2시간 후 다른 경보가 울렸을 때 다음 교대조는 설비가 정상 구성 상태에 있다고 잘못 판단하여 그릇된 조작을 하게 되고, 이는 연쇄 설비 트립으로 이어진다.

## 작업 전 검증과 원상복구 마감시한 (Back-Out Deadline)

예비 설비가 정상 가동 중일 것이라는 지레짐작으로 변경 작업을 시작하지 마라. 윈도우 개시 2시간 전(T-2 h), 당직팀은 작업 전 점검을 수행해야 한다:
- 살아남아 부하를 감당해야 할 모든 예비 설비(2N 전원선, N+1 냉각기, 비상 발전기)가 온라인 상태이며 안정적으로 운전 중이고 잠재 경보가 전혀 없음을 확인한다.
- 작업 윈도우 동안 악천후(낙뢰, 계통 불안정, 폭염) 예보가 없음을 확인한다.
- 외부 긴급 지원 업체(전력회사, 연료 공급사, 특수 서비스 벤더)가 비상 대기 상태임을 확인한다.

모든 MOP에는 명확한 **원상복구 마감시한(Back-Out Deadline)**이 포함되어야 한다. 복구 마감시한이란 작업 진행 경과와 무관하게 작업을 즉시 중단하고 설비를 원래의 정상 구성으로 되돌리는 절차를 시작해야 하는 절대적인 시점이다. 6시간 작업 윈도우에서 복구에 2시간이 걸린다면 복구 마감시한은 개시 후 정확히 4시간 시점(T+4 h)이다. 신규 부품이 그 시각까지 완전 검증되지 않았다면 기술자는 즉시 원상복구 절차를 밟아야 한다. 작업자의 "30분만 더 달라"는 사정을 결코 받아주지 마라.

## 기술적 인수 vs. 상업적 완료

외주업체가 공구함을 챙기고 청구서를 내민 채 문을 나섰다고 해서 변경이 종결된 것이 아니다. 변경이 진정으로 종결되는 것은 시설 관리자가 기준 SLA에 비추어 엄격한 기술적 인수를 마쳤을 때뿐이다:
- 개조·교체된 설비에 통전되어 열적·전기적 실부하 하에서 규정된 최소 안정화 시간(통상 30~60분) 동안 정상 가동되었는가.
- 텔레메트리 데이터가 운전 온도, 압력, 진동 프로파일, 전력 상 밸런스가 변경 전 기준과 일치함을 입증하는가.
- 작업 중 비활성화되었던 모든 경보가 다시 활성화되고 루프 테스트를 통해 정상 복귀가 확인되었는가.
- 사건기록장치(SOE)가 스위칭 중 기록되지 않은 과도 스파이크나 지락이 없었음을 확인해 주는가.

기술적 인수가 만족스럽게 완료되지 못할 경우 변경은 **"결함 잔존으로 인한 일시 중단"**으로 공식 분류되고, 장애 티켓이 발행되며, 지정 엔지니어의 지속 감시 하에 놓여야 한다.

## 기록할 결정

- 구 파라미터 값과 신 파라미터 값을 대조한 오늘의 변경 작업 대장.
- 각 변경 티켓에 대한 공식 위험 인수자의 성명과 직책.
- 각 유지보수 윈도우의 정확한 개시 및 종료 타임스탬프.
- 제어실 보드 및 인수인계 일지에 게시·해제된 비정상 운전 상태 기록.
- 실부하 조건 하에서 서명된 정식 기술적 인수 완료 기록.
