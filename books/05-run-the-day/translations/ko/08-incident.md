# 8. 설비가 고장 났을 때

인시던트(장애)란 중요 인프라가 계약된 서비스 범위를 제공하지 못하게 된 사건, 인명이 위험에 처한 사건, 또는 시설이 머지않아 두 가지 결과를 초래할 불안정한 상태로 진입한 사건을 말한다.

```
+-----------------------------------------------------------------------------+
| 장애 대응 및 에스컬레이션 타임라인 |
| |
| [T = 00:00] 장애 인지 (텔레메트리 트립, 경보 부저, 육안 목격) |
| | |
| [T + 02:00] 정지 및 상황 파악: 부저 정지, 고장 하위 계통 식별 |
| | |
| [T + 05:00] EOP 실행: 직전 안전 상태 확립, 위험 격리 |
| | |
| [T + 10:00] 장애대책반 소집: 사고 일지 개설, 역할 부여 |
| | |
| [T + 15:00] 고객 SLA 통보: 확인된 사실만 통보 (가설·추측 절대 금지) |
| | |
| [T + 60:00] 기술적 봉쇄: MOP 기반 복구 전개, 정기 상황 브리핑 |
| | |
| [사태 수습] 근본원인분석 (RCA): 왜왜 분석, 단 하나의 담당자 배정 시정 조치|
+-----------------------------------------------------------------------------+
```

서비스 제공이나 인명 안전을 위협하지 않는 시끄러운 경보는 성가신 소음일 뿐이다. 그것을 비상사태로 격상시키지 마라. 반대로, 장비실이 조용하고 평온해 보인다고 해서 실질적인 서비스 저하를 가볍게 여겨서도 안 된다. 인시던트를 측정하는 유일한 잣대는 서비스 제공 여부와 인원의 안전이다.

## 장애 심각도 등급 분류

모든 이상 사태는 인지 후 2분 이내에 세 가지 엄격한 심각도 등급 중 하나로 분류되어야 한다:

```
+-----------------------------------------------------------------------------+
| 장애 심각도 등급 분류표 |
| |
| 등급 분류 운영 영향 고객 통보 요구조건 |
| ------ ------------ ----------------------------- -------------------- |
| P1 핵심 (Critical) IT 부하 전력 또는 냉각 완전 상실; <= 15분 이내 통보; |
| 인명 안전 위협 사태 매시간 현황 갱신 |
| P2 주요 (Major) 시스템 이중화 상실 (N-1 상태); <= 30분 이내 통보; |
| 고온 경보 발생 2시간마다 갱신 |
| P3 경미 (Minor) 단일 부품 고장; 교대 일일 서머리에 |
| 시스템 이중화 영향 없음 기재 |
+-----------------------------------------------------------------------------+
```

## 첫 1시간: 인시던트 시계

실시간 장애 상황에서 인간의 기억은 아드레날린 때문에 급격히 왜곡된다. 기술자들은 조작 순서를 뒤바꿔 기억하고, 관리자는 20분간 망설였던 것을 5분 만에 내린 결단으로 미화한다.

당직 관리자는 사태가 시작된 바로 그 분부터 수정 불가능한 타임스탬프가 찍히는 **"장애 크로놀로지 일지"**를 개설해야 한다:

```
+-------------------------------------------------------------------------+
| 장애 크로놀로지 일지 |
| |
| [09:14:22] EPMS: B 계통 피더 차단기 B-SWG-02 순시 과전류 트립 접수 |
| [09:16:00] 당직 관리자: EOP-E-04 (2N B계통 상실 조치) 발동 |
| [09:18:45] 엔지니어 진: A 계통이 전체 부하의 82%를 정상 부담 확인 |
| [09:21:10] 안전 상태 1 도달: IT 부하 단일 피더 운전으로 안정 유지 |
| [09:24:00] 고객사 1차 SLA 공지 발송 완료 (포털 발송, T+10분) |
| [09:32:00] A 계통 배전반 열화상 스캔 실시, 58°C로 안정 확인 |
| [09:45:00] 수배전반 제조사 긴급 호출, 접수 번호 #84920 확인 |
+-------------------------------------------------------------------------+
```

모든 사건을 정확한 타임스탬프와 함께 기록하라:
- 모니터링 콘솔에서 경보가 감지된 정확한 분.
- 계측기에서 물리적으로 관찰된 사실(누군가의 가정이 아닌 육안 사실).
- 실행된 정확한 EOP 번호, 도달한 안전 상태, 그 상태가 확인된 분.
- 대책반에 소집된 모든 인원의 성명.
- 고객 통보문이 발송된 분과 발송된 정확한 문면.
- 살아남은 정상 계통을 보호하기 위해 의도적으로 거부하거나 미룬 조치.

## 반사적 안전 상태 확립 vs. 영웅적 트러블슈팅

경보가 울리고 장비가 트립되었을 때 훈련되지 않은 기술자가 본능적으로 보이는 반응은, 떨어진 차단기를 리셋하거나 바이패스 밸브를 열어젖히며 어떻게든 죽은 설비를 살려보려는 "영웅적 트러블슈팅"이다.

이러한 무모한 영웅 행세야말로 경미한 단일 설비 트립을 전체 데이터센터 대정전으로 확대시키는 주범이다:
- 순시 과전류로 트립된 차단기는 하류의 치명적인 선간 단락 고장을 막아낸 것일 수 있다. 원인 확인 없이 그 차단기를 재투입하면 폭발적인 아크 플래시가 발생하여 배전반 열 전체가 파괴된다.
- 저흡입압력으로 트립된 2차 CDU 펌프는 팽창 탱크 고갈이나 배관 파망을 의미할 수 있다. 확인 없이 예비 펌프를 강제 기동하면 메커니컬 씰이 타버리고 모터가 소손된다.

인시던트 상황에서의 절대적인 운영 철칙은 다음과 같다:
1. **비상대응절차(EOP)를 실행**하여 사전 설계된 가장 가까운 "안전 상태(Safe State)"를 확립하라.
2. **멈춰라(Stop)**. 조작반에서 손을 떼라.
3. 살아남은 이중화 설비가 안정적으로 부하를 감당하고 있는지 확인하라.
4. 승인된 MOP 하에서 체계적인 원인 조사를 시작하라.

사이렌이 울리는 와중에 통전 중인 장비를 고치려는 영웅은 액션 영화에나 어울리며 산업용 데이터센터에는 필요 없다. 산업용 데이터센터에서 존경받는 사람은 설비를 안전 상태로 수습하고 한 걸음 물러나 절차를 준수하는 규율 잡힌 기술자다.

## 1차 고객 공지에서 "가설"을 배제하라

고객에게 보낼 1차 장애 통보문을 작성할 때는 다음 철칙을 엄수하라: **"확인된 물리적 사실만 보고하라. 가설이나 추측은 완전히 배제하라."**

```
+-------------------------------------------------------------------------+
| 고객 통보의 규율 |
| |
| [허용되는 사실 중심 공지] |
| "UTC 09:14경, B 전력 피더에서 자동 차단이 발생했습니다. |
| 모든 중요 IT 서버 홀은 이중화된 A 피더를 통해 정상 급전되고 있습니다. |
| 시설은 현재 N-1 상태에서 안전하게 운영 중입니다. |
| 운영팀이 현재 B 피더 차단 원인을 조사하고 있습니다. |
| 다음 공식 현황 보고는 UTC 10:15에 제공될 예정입니다." |
| |
| [금지되는 추측성 공지] |
| "외주 작업자가 B 계통 계전기를 건드린 것으로 추정되거나, 인근에 낙뢰가 |
| 있었던 것 같습니다. 현재 차단기 리셋을 시도 중이며 10분 내에 복구될 |
| 것으로 기대하고 있습니다." |
+-------------------------------------------------------------------------+
```

1차 공지에 추측을 적어 보냈다가 사후 엔지니어링 분석에서 그것이 오판으로 밝혀지면:
- 운영 역량에 대한 고객의 신뢰는 완전히 파괴된다.
- 고객사 법무팀에 중대한 과실을 주장할 빌미를 제공하게 된다.
- 기술팀은 복구에 집중해야 할 시간에 초기 보고를 변명하고 해명하는 데 진을 빼게 된다.

증상, 발생 시각, 영향 계통, 현재 격리 상태, 다음 보고 시각만을 적어라. 그 외에는 아무것도 말하지 마라.

## 단 하나의 책임자 배정 시정 조치 (사후 RCA)

장비가 재통전되고 경보가 꺼졌다고 해서 인시던트가 끝난 것이 아니다. 공식적인 근본원인분석(RCA)이 수행되고 **"구체적이고 기한과 담당자가 지정된 단 하나의 시정 조치"**로 완결되었을 때에만 장애가 종결된다.

관계자들이 모여 당시의 공포를 회고하며 "앞으로는 더 조심하자"고 결론짓는 사후 검토 회의는 완전한 시간 낭비다. "더 조심하는 것"은 엔지니어링 통제 기법이 아니다.

진정한 시정 조치는 다음 중 하나를 물리적으로 바꾸는 것이다:
- 엔지니어링 설계 (예: 공통 모드 트립 회로를 제거하기 위한 분리 릴레이 추가 설치).
- 유지보수 절차 (예: 480V 단자대에 이중 토크 체크를 의무화하도록 MOP 개정).
- 순회 점검 항목 (예: CDU 일일 점검표에 현장 굴절계 측정 추가).
- 물리적 공구 및 자재 (예: 배관 내 공기 유입을 차단하는 진공 주입 스키드 도입).

시정 조치는 단 한 명의 담당자와 확고한 완료 기한을 가져야 한다. 사후 검토에서 모호한 권고 사항 5가지를 늘어놓으면 그중 어느 것도 실행되지 않는다. 가장 영향력 있는 구조적 대책 하나를 골라 담당자를 지정하고 일일 인수인계 일지에서 완료될 때까지 추적하라.

## 기록할 결정

- 장애 심각도 등급(P1 / P2 / P3) 및 정확한 인지 시각.
- 모든 조치, 도달한 안전 상태, 동원된 인원을 기록한 크로놀로지 일지.
- 추측성 가설이 완전히 배제되었음이 확인된 고객 1차 공지문 사본.
- 정상 실부하 상태에서 서명된 기술적 복구 확인 서명.
- 근본원인분석에서 도출된, 담당자와 완료 기한이 명시된 단 하나의 시정 조치.
