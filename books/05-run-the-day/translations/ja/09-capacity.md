# 9. 数字を作らない容量管理

施設管理者の日常的なキャパシティ管理の責務は、以下の3つの根本的な問いによって支配されている：
1. 契約上、顧客にどれだけの容量を販売したか？
2. 今この瞬間に、物理的にどれだけの容量が消費されているか？
3. 最大の単一コンポーネントが今すぐ壊れた場合、どれだけの容量が生き残るか？

検証された計測記録からこれら3つの問いに数学的確信を持って答えられないなら、あなたは今日提案されている保守作業やサーバー増設が安全であるかどうかを判断できていない。

## 2N冗長の数学：45%ルール

データセンター管理における最も蔓延し、かつ致命的な神話は、「2N冗長化された電気系統においては、各系統を定格容量の**50%まで**安全に使用できる」という誤った思い込みである。

これは業界全体でメガワット規模のカスケード全系停電を引き起こしてきた数学の罠である：

$$P_{\text{total}} = P_{\text{Bus A}} + P_{\text{Bus B}}$$

定格 2000 kVA の2N受配電母線を例に考える。運用管理者は、A系統が 1040 kVA（負荷率52%）、B系統が 1020 kVA（負荷率51%）で稼働しているのを見て、どちらの母線も定格を超えていないため安全マージン内にあると判断した。

ここで、A系統の上流変圧器がトリップしたとする。
数ミリ秒以内に、A系統に接続されていたすべてのデュアルコードITサーバー電源ユニットが、全電力をB系統へとシフトさせる。

このときB系統にかかる瞬間的な総負荷は以下の通りとなる：

$$P_{\text{Bus B, transient}} = 1040\,\text{kVA} + 1020\,\text{kVA} = 2060\,\text{kVA} \quad (\text{定格容量の } 103\%)$$

B系統は即座に過負荷に陥る。B系統の主遮断器が持続的な過電流を検知し、限時トリップ曲線に従って遮断動作を行い、データホール全体が漆黒の闇に沈む。完全な2N耐障害性を持つはずだった施設が、単一機器のトリップから全系ブラックアウトを引き起こしたのである。

このようなカスケードトリップを絶対に防ぐため、すべての2N配電系統は**「45%ルール」**を厳格に遵守しなければならない：

$$P_{\text{steady-state}} \le 0.45  \times P_{\text{rated}}$$

45%ルールのもとでは：
- A系統の定常負荷 ≤ 45%（900 kVA）。
- B系統の定常負荷 ≤ 45%（900 kVA）。
- A系統がトリップした場合、生き残ったB系統が引き受ける総負荷は 900 + 900 = 1800 kVA（定格の 90%）。
- B系統は10%の安全裕度を持って安定稼働を維持し、熱動電磁トリップ閾値の手前に留まるため、技術員は落ち着いて事態を収束させることができる。

2N母線の定常負荷率が45%を超えることを容認するシフト管理者は、施設の冗長性を破壊し、定格外の高リスク状態で施設を危険に晒している。

## 二次冷却ループの水力容量

ラックあたり最大 132 kW を消費するNVIDIA NVL72のような超高密度計算ラックを収容する液冷ホワイトスペースでは、水力容量の管理は電気容量の管理と同等に致命的である：

**CDU水力容量シーリング**

| パラメータ 設計定格限界 運用冗長限界 |  |  |
| :--- | :--- | :--- |
| 総吸熱能力 1200 kW / CDU | <= 1000 kW (PHE定格の83%) |  |
| 二次側流量 1440 LPM (24 | LPS) <= 1200 LPM (単独ポンプ N | ) |
| 供給液温 25.0°C 〜 32.0° | C (W3/W4) <= 30.0°C (最高外気 | 温時) |
| ポンプ構成 N+1 デュアルVFDポン | プ 1台稼働 / 1台自動待機 |  |
| ループ圧力 0.15 〜 0.90 M | Pa 配管圧損差圧 < 1.0 bar |  |

顧客から高密度液冷ラックの増設要請を受けた際、当直管理者は以下の水力学的制約を検証しなければならない：
1. **総供給可能流量**：コールドプレート内で乱流熱伝達を維持するために必要な体積流量（q_v）を二次ポンプが供給できることを確認する：

$$q_v = \frac{Q}{\rho \cdot c_p \cdot \Delta T}$$

ここで：
- Q は総発熱量（ kW）。
- $\rho$ は25%プロピレングリコール水溶液の密度（30°Cにおいて$1026\,\text{kg/m}^3$ ）。
- c_p は定圧比熱（3.92 kJ/( kg· K)）。
- ΔT はラックマニホールド前後の流体温度上昇（通常 10.0 K）。

2. **水力的不平衡とダイレクトリターンの流量飢餓**：二次分配マニホールドにラックを追加していくと、管路摩擦損失（ΔP_f）は流速（v）の2乗に比例して増大する：

$$\Delta P_f = f \cdot \frac{L}{D} \cdot \frac{\rho v^2}{2}$$

配管がリバースリターン（ティッヘルマン方式）ではなくダイレクトリターンで施工されている場合、列の末端に負荷を追加すると、最遠端のインデックスラックで流量飢餓が発生し、GPUの熱保護サーマルスロットリングが即座に誘発される。

「ポンプは十分大きそうに見えるから大丈夫」という顧客の口頭保証に基づいて液冷の増設を承認してはならない。接続許可を発行する前に、検証済みの水力シミュレーション報告書と圧力損失計算書の提出を要求せよ。

## 通電して試してみるという迷信

計算上の許容容量を超えるサーバーラックの増設許可を求めてきた顧客や設置プロジェクトチームは、しばしばこう提案してくる：
> *「とりあえずラックに通電してみて、遮断器がもつかどうか20分間メーターを見守ってみましょう。」*

これは、30トントラックを氷の上に走らせて氷の厚さを確かめるような自殺行為である。

「もつかどうか試すために」通電することは：
- 配電母線や変圧器に巨大な突入電流と熱衝撃を与える。
- 上流の保護継電器を誤作動させ、隣接する稼働中テナントに瞬時停電を引き起こすリスクを冒す。
- 厳密なエンジニアリング計算を無謀なギャンブルに置き換えるものである。

要求された負荷の投入が、契約上の割当枠または45%冗長シーリングのいずれかを超過している場合、当直管理者は直ちに許可を拒絶しなければならない。通電を阻止せよ。顧客は正式な技術検討書を提出し、新たな遮断器を1本投入する前に契約変更の合意を取り付けなければならない。

## 記録する決定

- 契約条項およびラック番号によって引用された、契約上販売済みの容量。
- 母線ごとに記録された実効電力負荷（45%冗長ルールの遵守確認）。
- CDUごとに記録された二次冷却ループ流量、供給温度、および差圧。
- 最悪の単一故障が発生した後の残余容量：公認技術検討書に基づく検証値、または「未知」の記録。
- 安全容量を超過するあらゆる通電要請を書面で拒否した記録（「試運転」の完全排除）。

## 物理的責任分界（デマーケション）と定量的シフト監査プロトコル

シフト運用管理者は、設備の物理的境界（Ring 1: 受電・外構、Ring 2: 中央熱源・特高変電、Ring 3: ホール配電・二次CDU、Ring 4: 顧客ラック内部）における責任分界点（`DEMARC`）を厳格に維持し、以下の定量的監査基準を当日シート（Day Sheet）に記録しなければならない。
