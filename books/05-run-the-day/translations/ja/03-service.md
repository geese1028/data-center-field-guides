# 3. 販売したサービス

顧客はあなたのディーゼル燃料タンク、チタン製プレート熱交換器、あるいは現場への個人的な献身を買っているのではない。顧客が買っているのはSLA（サービス品質保証契約）である。すなわち、電力の可用性、熱的供給限界、障害エスカレーションの時間を数学的に定義した契約である。マスターサービス契約書の正確な条項を引用できないなら、あなたの運用は根拠のない伝聞に基づいている。

## 契約限界値とエンジニアリングマージン

データセンターの運用においては、以下の3つの異なる境界を明確に区別しなければならない：
1. **設計設定値（Design Setpoints）**：制御ループに組み込まれた最適運転目標（例：CDU二次側供給液温 28.0°C、コールドアイル吸気温 22.0°C）。
2. **社内警報閾値（Operational Alarm Limits）**：顧客影響が発生する前に技術員が是正措置を講じるための内部閾値（例：二次側供給液温が 30.5°C に達した時点で待機ポンプ起動や冷凍機追従を促す）。
3. **契約逸脱限界（Contractual Breach Limits）**：サービス対価の減額ペナルティや契約不履行通知の対象となる法的なSLA境界（例：二次側液温が 32.0°C を連続して5分間超過、またはラック吸気温が 27.0°C を超過）。

顧客の営業担当者が、内部の社内警報を契約違反として騒ぎ立てることを許してはならない。逆に、「わずか3分間スパイクしただけだから」という理由で、SLA閾値を超過した温度異常を現場チームが見過ごすことも絶対に許されない。契約が60秒の移動平均で逸脱を判定する取り決めになっているなら、3分間のスパイクは立派なSLA違反である。正確にログへ刻め。

## 可用性の計算式

データセンターの稼働率（可用性 A）は次式で算出される：

$$A = \frac{\text{総期間時間（分）} - \text{停止時間（分）}}{\text{総期間時間（分）}}  \times 100\%$$

最新のマルチテナント型コロケーションやハイパースケール専用棟契約において、「停止時間（Outage Minutes）」は極めて厳密な法的定義を持つ：
- 2N電源ラックにおいて、A系統とB系統の双方が喪失した場合のみを停止とするのか、片系喪失（冗長性喪失）も按分して停止時間に含めるのか。
- 顧客のサーバーがB系統で正常稼働を継続している間にA系統が遮断された場合、SLAの障害時計は進むのか。
- 液冷CDUがデュアルポンプのN+1冗長から単独ポンプ運転に縮退したが、熱的ディレーティングは発生しなかった場合、これは停止に該当するのか。

当直管理者は、インシデントが発生する前にこれらの契約的解釈を完全に把握していなければならない。有事の現場において、外部の企業弁護士に相談している時間はない。

## 通知期限時計（Notice Period Clock）

設備の逸脱がSLA閾値を超えた瞬間、時計は即座に動き出す：

$$\Delta t_{\text{notice}} = t_{\text{sent}} - t_{\text{detect}} \le T_{\text{contractual}}$$

多くのハイパースケールSLAでは、最初の異常検知から**15分以内**（T_contractual ≤ 15 min）の正式通知が義務付けられている。

| **15分間通知ウィンドウ** |
| :--- |
| T = 00:00 BMS/EPMSで警報発報、トリップ検知 |
| T + 05:00 当直管理者が事象を確認、安全状態への隔離を指示 |
| T + 10:00 第1報起草：症状、発生時刻、影響範囲（棟・ホール） |
| T + 14:00 顧客技術窓口へ正式送信（ポータル・メール） |
| T + 15:00 契約上の通知期限到来 |

初心の運用管理者にありがちな最大の失敗は、技術員が根本原因を調査している間、顧客への第一報を遅らせることである。これは契約上の大惨事である。顧客は、数分で安全状態に収束した変圧器トリップを許容することはあっても、自社の監視モニタでサーバーが停止しているのを見てから40分間もデータセンター側が無言であったことを決して許さない。

12分目に通知を送れ。確認された物理的事実のみを記せ：発生時刻、影響を受けた電気母線または冷却系統、現在の非常用バックアップの稼働状況、および次回報告予定時刻である。原因に関する憶測は絶対に文面に紛れ込ませてはならない。

## 約束外の数値を報告するな

契約書に明記された項目のみを測定し、報告せよ。PUE（電力使用効率）、CUE（炭素使用効率）、WUE（水使用効率）などの社内運用指標を算出することは、設備の省エネ改善やESG報告にとって重要である。しかし、契約書がPUEを課金条件やSLA項目として明確に定義していない限り、日々のSLA納品証明書に社内PUEの数値を記載してはならない。

契約外の効率比率を日次の公式ログに記載すると、社内の技術的努力目標が外部の攻撃対象へと変貌し、顧客が請求金額を争う口実に利用されることになる。契約上の保証ログと、社内の分析データは厳格に分離せよ。

## 記録する決定

- 今日のサービスを規定するマスター契約書の正確な題名、補遺番号、該当条項。
- 契約上の時間計測に用いられる公式テレメトリメーターIDと時刻同期ソース。
- 契約上の通知許容時間（T_contractual、分単位）。
- シフト中に発生したすべてのSLA逸脱記録（事象記録装置のミリ秒単位のタイムスタンプ付き）。

| :--- | :--- | :--- | :--- |
