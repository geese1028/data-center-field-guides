# 5. 変更

データセンターにおける破滅的な全系障害の大部分は、落雷や地震、あるいはメーカーの製造欠陥によって引き起こされるのではない。ほとんどの破滅的障害は、「日常的な定常保守」として安易に分類された変更作業によってもたらされる。

```
+-----------------------------------------------------------------------------+
| 変更実行ライフサイクル |
| |
| [T - 72h] 技術事前審査：リスク評価、単一障害点（SPOF）監査 |
| | |
| [T - 24h] 変更諮問委員会 (CAB) 承認：書面によるリスク受諾 |
| | |
| [T - 02h] 作業前確認：冗長系統が100%健全、警報ゼロであることを確認 |
| | |
| [T = 00h] 保守ウィンドウ開始：中央監視盤に「異常縮退状態」を掲示 |
| | |
| [T + 実行] ツーマンルールに基づくMOP手順のステップ実行 |
| | |
| [T + 検証] 実負荷機能検証：テレメトリにより正常運転を証明 |
| | |
| [T + 完了] 変更後サインオフ：異常縮退の解除、引き継ぎ日誌更新 |
+-----------------------------------------------------------------------------+
```

## 何が変更に該当するか

変更とは、以下のいずれかを変化させるすべての物理的、電気的、機械的、論理的操作を指す：
- 過渡状態においてインフラ機器がどのように故障するか（故障モード）。
- 技術員によってプラントがどのように監視され、操作され、制御されるか。
- 顧客に提供されている冗長構成、容量、または電力・流体経路。

表示用LEDを純正の同一部品と交換することは、電気的隔離を必要とせず、制御母線の短絡リスクがない限り「保守」である。しかし、遮断器をトリップ特性の異なるものに交換すること、インバータの加減速レートを変更すること、中央監視システムのPID制御パラメータを変更すること、あるいはCDU二次側の供給温度設定をわずか 0.5 K 変更することはすべて「変更」である。

サーバー負荷を電気A系統からB系統へ切り替える操作は、たとえ20分間だけであっても重大な「変更」である。A系統が切り離されている間にB系統で予期せぬ過渡サージが発生すれば、データセンター全体が沈黙する。ある現場操作が保守か変更かで少しでも議論が生じるなら、迷わず「変更」として扱え。

## 変更諮問委員会（CAB）とリスク受諾

すべての変更作業は、実施前に変更諮問委員会（Change Advisory Board: CAB）の正式承認を経なければならない。

CAB申請書類には以下が明記されていなければならない：
1. **運用の正当性**：「点検業者が別の作業でたまたま来所していたから」は正当な理由にならない。記録された不具合の解消、契約済みの増設対応、特定された安全リスクの低減のみが正当な理由である。
2. **運用リスクレベルの分類**：
 - **レベル1（クリティカル）**：本番IT負荷を支える稼働中の受配電設備や一次冷却系統に触れる侵襲的作業。運用統括責任者の署名と顧客への事前通知が必須。
 - **レベル2（メジャー）**：冗長系統（N+1）の片系作業。作業ウィンドウ中に稼働側が故障した場合に顧客影響を及ぼす作業。
 - **レベル3（マイナー）**：補助設備や独立支援系に対する非侵襲作業。物理的・電気的分離により本番影響が完全に排除されている作業。
3. **リスク受諾者（Risk Acceptor）**：変更に伴うリスクを書面で引き受ける契約上・財務上の権限を持つ上級責任者の氏名。現場でトルクレンチを握る技術員はリスク受諾者ではない。指名されたリスク受諾者と連絡がつかない場合、保守ウィンドウを開いてはならない。

## 異常運転状態（Abnormal State）の掲示

保守ウィンドウの間、プラントは一時的な**異常運転状態（Abnormal Operating State）**に入る。

この異常運転状態の内容は、以下のように明確に可視化されなければならない：
- 中央監視室のホワイトボードに大きく太字で掲示する。
- すべての監視端末のBMS画面上部にデジタルバナーで警告表示する。
- シフト引き継ぎ日誌に明記する。

```
+-------------------------------------------------------------------------+
| 中央監視室・異常運転状態掲示板 |
| |
| [現在の異常縮退] 冷凍機 CH-03 凝縮器開放点検のため隔離中 |
| [残余冗長性] 全4台中3台稼働中；現在の冗長性 = N+0（冗長喪失） |
| [潜在リスク] CH-01 または CH-02 のトリップで自動負荷遮断が発動 |
| [作業時間枠] 2026-10-14 10:00 〜 14:00 UTC | リスク受諾者: J. Vance|
| [切り戻し刻限] 13:00 UTC（これまでに復旧未着手なら直ちに中止・復旧） |
+-------------------------------------------------------------------------+
```

ボルトの締め付けが物理的に完了したからといって、監視盤や日誌の異常状態掲示を解除しないまま放置することは重大な運用ハザードである。2時間後に別の警報が鳴ったとき、後番のシフト員は設備が正常構成にあると誤認して判断を誤り、誤操作によるカスケードトリップを引き起こすことになる。

## 作業前確認と切り戻し刻限（Back-Out Deadline）

冗長系統が動いているはずだという思い込みで変更作業を開始してはならない。ウィンドウ開始の2時間前（T-2 h）、当直チームは作業前点検を実施しなければならない：
- 生き残り側となる予備系統（2N電源系統、N+1熱源系統、非常用発電機）がすべてオンラインで安定稼働し、潜在的な警報が一切ないことを確認する。
- 作業ウィンドウ中に悪天候（落雷、系統不安定、猛暑）の予報がないことを確認する。
- 外部緊急対応ベンダー（電力会社、燃料納入業者、専門保守業者）が待機体制にあることを確認する。

すべてのMOPには、明確な**切り戻し刻限（Back-Out Deadline）**が設定されていなければならない。切り戻し刻限とは、作業の進捗状況にかかわらず、それ以上作業を進めることを中止し、プラントを元の基準構成に戻す作業を開始しなければならない絶対的な時刻である。6時間の作業枠で復旧に2時間かかるなら、切り戻し刻限は開始からちょうど4時間後（T+4 h）である。その刻限までに新規機器の健全性が確認できていないなら、技術員は直ちに切り戻し手順に入らなければならない。「あと30分だけ待ってくれ」という業者の懇願を決して受け入れてはならない。

## 技術的検収と商用完了の分離

ベンダーが工具箱を閉じ、請求書を差し出して門を出たからといって、変更がクローズしたわけではない。変更が真にクローズするのは、施設管理者が実負荷下での厳格な技術的検収を終えたときだけである：
- 改造・交換された機器に通電され、熱的・電気的実負荷下で規定時間（通常30〜60分間）の慣らし運転（ドウェル）が完了していること。
- テレメトリデータにより、運転温度、圧力、振動スペクトル、相間電流バランスが変更前の基準値と一致していることが証明されたこと。
- 作業中にバイパスまたは無効化されていたすべての警報が再有効化され、ループテストによって正常復帰が確認されたこと。
- 事象記録装置（SOE）のログにより、切替中に過渡サージや地絡が生じていないことが確認されたこと。

技術的検収が満足に完了しない場合、その変更は**「不具合残存による一時停止」**として公式に分類され、インシデントチケットが発行され、指名された主任技術者による継続監視下に置かれなければならない。

## 記録する決定

- 変更前の旧パラメータ値と変更後の新パラメータ値を対比した、本日の変更台帳。
- 各変更チケットに対する正式なリスク受諾者の氏名と役職。
- 各保守ウィンドウの正確な開始および終了タイムスタンプ。
- 監視室ボードおよび引き継ぎログに掲示・解除された異常運転状態の記録。
- 実負荷条件下で署名された正式な技術的検収確認記録。
