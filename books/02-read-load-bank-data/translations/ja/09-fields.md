# 9. 自動化フィールドと人間の判断

最新のコミッショニングプラットフォームでは、自動化されたデータ取り込みスクリプト、Pythonパイプライン、およびクラウドダッシュボードを用いて、毎秒数千点ものModbusやMQTTのテレメトリデータを取り込んでいる。自動化は効率的かつ一貫性があり、手作業による計算疲労とも無縁である。

しかしながら、数値を計算する自動化スクリプトと、技術的検収（アクセプタンス）を認可する自動化スクリプトを決して混同してはならない。

速報では、以下の2つの明確に異なる記入セルのカテゴリー間に、妥協のない境界線を確立する：
1. **スクリプト入力セル（Script-Filled Cells）**：生テレメトリから決定論的に算出される算術量および統計量。
2. **人間入力セル（Human-Filled Cells）**：定性的な合否判定、契約適合性の決定、および技術的検収に関する法的な署名。

アルゴリズムはプロフェッショナルエンジニア（PE）の資格を保有しておらず、法廷に出廷することもできず、データホールの火災に対して金銭的または運用上の責任を負うこともできない。アルゴリズムは数値を計算し、人間が判定を下すのである。

## スクリプトの入力が許可される範囲

自動化スクリプト、取り込みパイプライン、およびデータベース集約クエリは、決定論的な数学的処理に極めて適している。スクリプトは、人手を介することなく以下のフィールドを自動入力することが認められ、またそうすべきである：

- **タイムスタンプおよびサンプル数**：ミリ秒単位の正確な開始・終了時刻、秒単位の保持継続時間、およびチャネルごとに受信された有効な未加工1秒サンプルの総数。
- **統計的要約量**：定義された時間ウィンドウ内における算術平均値（μ）、最小値（$\min$）、最大値（$\max$）、標本標準偏差（σ）、および分散（σ²）。
- **物理的派生計算量**：質量流量（ṁ），流体バルク密度（ρ）、定圧比熱（C_p）、液体エンタルピー吸収量（Q_liquid）、および付随空気顕熱量（Q_air）。
- **複数ラック間メトリクス**：並列ラック間におけるグループ平均値、グループ標準偏差、および変動係数（CV）。
- **エンタルピークロージャ比率**：有効電力消費と総熱力学的放熱量との間の正確なパーセンテージクロージャ（P_elec 対 Q_liquid + Q_air）。
- **アルゴリズムによる異常検知フラグ**：分散ゼロのフラットライン（σ² ≤ 1.0 × 10^{-4}）、通信途絶ギャップ、測定範囲外のセンサー読み取り値、ならびにFocus、FLOC、CPOP等からの変化点候補トリガー時刻を示す自動警告。

計算機は、電卓を手にした人間よりもはるかに高速かつ精密に算術演算を実行する。算術計算はスクリプトに任せよ。

## スクリプトの書き込みが厳格に禁止される事項

自動化スクリプト、ダッシュボードマクロ、またはAIモデルが、いかなる状況下でも以下の単語を自動生成することは固く禁じられる：
- **PASS（合格）**
- **FAIL（不合格）**
- **NOT RUN（未実施）**
- **WAIVED（適用免除）**

ある行を評価した自動化スクリプトが、上限値 46.0°C に対して算出された温度が 45.1°C であることを観測し、PDF上に自動的に「PASS」の印を捺印した場合、そのスクリプトは自らの権能を完全に逸脱している。

### 自動「合格」判定が危険である理由
アルゴリズムが決して知ることができない以下の事象を考察せよ：
- アルゴリズムは、45.1°C を報告しているRTDが、活発に流動する主流部ではなく、低温で流動のない止水管（デッドレグ）に誤って設置されていたことを知る由もない。
- アルゴリズムは、ラックの背後で仮設バイパスホースが折れ曲がっていたことや、保持時間中に記録のない手動バルブ調整が行われていたことを知る由もない。
- アルゴリズムは、当日の朝に発注者側から緊急の口頭通知が出され、試験許容上限が 46.0°C から 44.0°C へ引き下げられていたことを知る由もない。

「PASS」を書き出す自動化スクリプトは、エンジニアリングチームを誤った安心感へと誘惑する。「適合性の判定はソフトウェアがやってくれている」と思い込み、オペレーターは実際の配管を見なくなり、ポンプのキャビテーション異音に耳を澄まさなくなり、計器の校正タグを確認しなくなる。

本フィールドガイドにおいて、速報テンプレート上の判定セルは白紙として生成される。そこに記入できるのは、インクペンを持った人間の手、または認証された暗号論的デジタル署名のみである。

## 人間による不正な上書きの罪

これと逆の障害モードもまた同様に有害である：スクリプトによって計算された不合格の数学的セルを見た人間が、勝手に判定を「PASS」へと上書きしてしまう行為である。

最大許容閾値 **5.0%** に対してスクリプトが流量CVを **7.2%** と正しく算出した場合、エンジニアがそのセルの横に「PASS」と書き込み、*「流量はやや不均一であったが、全体的な冷却は良好に見えた」*などという口頭の言い訳を付け足すことは許されない。

その行為はエンジニアリング上の解釈ではない。記録のない不法な免除（ウェイバー）である。

算出されたセルが不合格を示した場合：
- その行に対する人間の判定は**FAIL（不合格）**でなければならない。
- 不合格となった事象がコミッショニングの広範な主目的を損なわないとプロジェクトチームが真摯に確信する場合、シートオーナーは正式な**免除プロトコル（Waiver Protocol）**を発動しなければならない：
 1. 設計基準仕様書を改定し、許容差を明示的に5.0%から7.5%へと緩和する。
 2. 新たな文書改定記号（例：Rev 2.5）を付与する。
 3. 当該の主張を「既知の制約事項」として正式に再分類する。
 4. 施設発注者（オーナー）から書面による署名済み承認を取得する。

更新された文書改定番号を伴い、白日の下で正式に承認された免除は、監査可能なエンジニアリング上の意思決定である。一方、表計算シートの片隅で不合格セルを人間が密かに「PASS」へと書き換える行為は、試験記録の改ざんにほかならない。

## 2列インターフェースの設計

ソフトウェアおよび印刷物においてこの規律を徹底するため、すべての速報テンプレートは厳格な**2列インターフェース（Two-Column Interface）**を実装しなければならない：

| 左列：自動データブロック（スクリプト所管） | 右列：評価および合否判定（人間所管） |
| :--- | :--- |
| • 指令電力：120.0 kW | • 引用限界基準：DOC-SPEC Rev 2.4、表2 |
| • 実測電力：120.2 kW | • 給電平衡度の検証：相不平衡率 < 1.0% |
| • 推定液体熱量：98.6 kW | • 熱力学的妥当性：確認完了 |
| • エンタルピークロージャ：98.0% | • ハードウェア目視点検：漏液なし／異音なし |
| • 算出流量CV：2.95%（σ = 5.21 LPM） | • 一貫性の検証：5.0%閾値内で合格 |
| • 品質マスク：0x0007（有効、σ² > 0） | • **人間の判定**：**PASS（合格）**［イニシャル：E.V., Lead CxA］ |

左列にはコードによって生成された無加工の数値が収まる。右列には人間の精密な点検、手動検証の確認結果、および最終的な責任者の署名が収まる。

## 記録すべき決定事項

速報のガバナンスセクションにおいて、以下を記録すること：

- 自動データ集約パイプラインのソフトウェアバージョン、スクリプトのチェックサム（SHA-256ハッシュ）、およびリポジトリブランチ。
- すべての判定セル（Pass/Fail/Not Run）が、指定された人間の権限者によって手作業で審査・入力されたことを証明する宣誓文。
- 試験キャンペーン中に発動された正式な免除（ウェイバー）の記録。承認された文書改定番号および発注者の署名を明記すること。
