# 14. テレメトリ取得、Modbus-TCP、およびMQTTパイプライン

速報や自動生成グラフの誠実さは、その記入セルを埋めるデジタルテレメトリパイプラインの誠実さを超えることはできない。

最新のメガワット規模データセンター試験において、テレメトリデータが魔法のようにデータベース内へ突如現れるわけではない。それは一連の個別物理的・デジタル的ホップ（中継段階）を経由して到達する：接液浸漬型RTD素子から、ローカルA/D変換器（ADC）、産業用Modbus-TCPフィールドバス、エッジ収集ゲートウェイ、そしてMQTTメッセージブローカーを経由して、改ざん不能な時系列データストアへと送られるのである。

この伝送連鎖の内部で、いずれか1つのホップでもサイレント障害（気付かれない停止）を起こした場合——例えばエッジポーラーが未更新のメモリバッファに対して新しいタイムスタンプを勝手に打刻し続けたり、あるいはMQTTブローカーが前日のキャッシュされた「Retained（保持）」メッセージを配信したりした場合——生み出される速報は完全な虚構と化す。

本章では、各ホップの技術仕様を定義し、データの完全性を保証するために必要とされる正確なModbusレジスタ構造、バイト順序規則、品質ビットマスク（Quality Bitmask）アーキテクチャ、およびMQTTペイロードスキーマを詳細に解説する。

（エンドツーエンドのテレメトリホップアーキテクチャ、IEEE-754ワードスワップの罠、16ビット品質ビットマスクレジスタ、および標準化されたJSONペイロードスキーマについては図02を参照）。

## ホップ1＆2：物理センサーからローカル変換器まで

データの旅は、物理的なプロセス境界から始まる：
- **温度**：マニホールドドロップ配管の中心コア流（内径の $1/3 \sim 1/2 D$）に直接浸漬された4線式クラスA Pt100 RTD素子。45°傾斜サーモウェル（保護管）内部に酸化亜鉛熱伝導コンパウンドとともに充填。
- **体積流量**：パルスまたは高周波デジタル周波数出力を備えたインラインカルマン渦流量計。動作温度帯全域における流体粘度変化の影響を受けない。
- **差圧**：管壁に対して垂直に穿孔され、平滑に研磨された静圧タップに接続されたピエゾ抵抗式静差圧伝送器。

変換器において、高精度な24ビットΣΔ（シグマデルタ）ADCが物理ブリッジ回路を 1 kHz でサンプリングし、ローカルのデジタル移動平均フィルターを適用して、毎秒1回（**1 Hz**）の校正済み測定値を出力する。

## ホップ3：Modbus-TCPフィールドバスアーキテクチャ

負荷装置の内部コントローラーは、標準的な産業用**Modbus-TCP（イーサネットポート502）**またはModbus-RTU（115,200 baud、8-N-1で動作するRS-485シリアルバス）を介してその運用パラメータを公開する：

- **ディスクリートコイル（機能コード 0x01 / 0x05）**：バイナリ制御状態——電磁弁開閉位置（V-101開／閉）、浸漬ヒーター接触器フィードバック接点状態、非常停止回路導通性、および漏液検知ロープリレー状態。
- **入力レジスタ（30001番台以降、機能コード 0x04）**：ローカルハードウェアADCチャネルによって直接生成される読み出し専用のセンサー測定値。
- **保持レジスタ（40001番台以降、機能コード 0x03 / 0x06 / 0x10）**：指令負荷設定値、動作モード設定、およびアラーム限界閾値。

### IEEE-754 32ビット浮動小数点数ワードスワップの罠
単一の16ビットModbusレジスタには、32ビット浮動小数点数（実数）の工学単位（例：45.12°C の温度測定値など）を格納することはできない。浮動小数点数値には、連続する2つの16ビットレジスタ（合計4バイト）が必要となる。

マイクロコントローラーのアーキテクチャによって、採用されているワード順序規則が異なる。エッジゲートウェイ側でワード順序を誤認してパースした場合、数値は完全に破綻する：
- **CDAB（ワードスワップ付きビッグエンディアン）**：Modbus浮動小数点数における業界標準。
 - レジスタ 40001 = `0x4234`、レジスタ 40002 = `0x0000` $\implies$ 正しく **45.00°C** と評価される。
- **ABCD（直接ビッグエンディアン）**：
 - レジスタ 40001 = `0x0000`、レジスタ 40002 = `0x4234` $\implies$ **1.87 × 10^{-38}** と評価される（極小のゴミデータ！）。
- **BADC（バイトスワップ付きリトルエンディアン）**：全く異なる無意味な任意の値として評価される。

速報の作業セットアップシートには、コントローラーファームウェアが使用している正確なワード順序規則を明記しなければならない。コミッショニング中に温度が季節外れの値へ突如跳ね上がる現象は、環境の奇跡などではない。未検証のワードスワップ解釈エラーである。エッジゲートウェイの設定側でパース処理を修正せよ。受信した未加工の生16進バイトを直接書き換えてはならない。

### 必須の16ビット品質ビットマスクレジスタ（Reg 40050）
品質フラグを伴わない生の数値は、未検証の単なる主張にすぎない。負荷装置コントローラーは、内部ファームウェア診断によってリアルタイムで更新される専用の**16ビット品質ビットマスクレジスタ（Register 40050）**を保持しなければならない：

- **ビット0（`0x0001`）**：`SUPPLY_TEMP_VALID`（1 = 健全、0 = 故障／断線）
- **ビット1（`0x0002`）**：`RETURN_TEMP_VALID`（1 = 健全、0 = 故障／断線）
- **ビット2（`0x0004`）**：`FLOW_METER_VALID`（1 = 健全、0 = 故障／パルス喪失）
- **ビット4（`0x0010`）**：`SENSOR_STALE_ALERT`（ADCが3秒以上同一値を繰り返した場合にアサート）
- **ビット5（`0x0020`）**：`COMM_TIMEOUT`（内部変換器バスのタイムアウトが250msを超えた場合にアサート）
- **ビット6（`0x0040`）**：`OUT_OF_RANGE`（RTD抵抗値が物理的許容枠を逸脱した場合にアサート）

レジスタ40050のビット4、5、または6がアサートされた場合、エッジゲートウェイはその測定値を直ちに**故障（FAULT）**として分類し、破損した数値を下流へ配信するのではなく、欠損ギャップとしてログに記録しなければならない。

## ホップ4：エッジゲートウェイのアクティブポーリング

エッジゲートウェイは、負荷装置のModbusコントローラーに対してクエリを発行する決定論的な 1 Hz ポーリングループを実行する：
- ポーラーは、1,000ミリ秒ごとに連続して入力レジスタおよび品質レジスタを照会する。
- **タイムアウトポリシー**：Modbusスレーブが250ミリ秒以内に応答しなかった場合、ポーラーはその秒の記録として**通信タイムアウト（COMMUNICATION TIMEOUT）**をログに記録する。
- **前値塗りつぶし（ペインティング・フォワード）の厳禁**：エッジゲートウェイが直前の正常な読み取り値をキャッシュし、それに新しい秒のタイムスタンプを貼り付けて出力することは固く禁じられる！空欄セルを防ぐために前回の数値を塗りつぶして引き延ばす行為は、意図的なデータ捏造である。ポーリングの失敗は `NaN` または `MISSING` として記録されなければならない。3回連続してポーリングに失敗した場合、そのプラトーは**無効（INVALID）**とマークされる。

## ホップ5：MQTTテレメトリブローカーおよびJSONスキーマ

エッジゲートウェイは、現場の1秒生テレメトリをパッケージ化し、ローカルのMQTTメッセージブローカーへ発行（パブリッシュ）する：
- **トピック階層**：整然とした階層的アセットトポロジーに従わなければならない：
 `dc/[hall_id]/[rack_id]/telemetry`（例：`dc/hall-03/lb-01/telemetry`）
- **QoS（サービス品質）**：ネットワークスイッチの瞬断によるパケット喪失を防止するため、ローカル永続化バッファリングを備えた **QoS 1（少なくとも1回配信）** を使用しなければならない。

### JSONテレメトリスキーマ
ブローカーに発行されるすべてのメッセージは、タイムスタンプ、電気、水力、および品質ブロックを含む標準化されたJSONスキーマに準拠しなければならない：

### 禁じるべき2つの致命的なMQTTの悪癖
1. **Retainedメッセージの罠**：MQTTプロトコルでは、パブリッシャーがメッセージに「retained」フラグを付与すると、ブローカーはそのメッセージを永続保存し、後から接続してきた新しいサブスクライバーに即座に配信する。自動速報スクリプトがブローカーに接続してretainedメッセージを取り込んだ場合、3日前の工場試験時に発行された古い測定値を取り込んでしまう恐れがある！試験計画書には以下を義務付けなければならない：**すべてのテレメトリパブリッシャーは `retained = false` を設定すること**。
2. **Last-Will-and-Testament（遺言メッセージ）の誤認**：エッジゲートウェイが予期せず切断された際にブローカーから発行されるLast-Will-and-Testament（LWT）メッセージは、明確な通信途絶ペイロード（`{"status": "OFFLINE", "quality": "DEAD"}`）を発行しなければならない。レポートエンジンはこのペイロードを即座に認識し、保持タイマーを直ちに一時停止しなければならない。

## 加熱前データ陳腐化プルーフテスト

試験当日に熱負荷を指令する前に、試験チームは**加熱前データ陳腐化プルーフテスト（Pre-Heat Stale Proof Test）**を実施しなければならない：
1. データパイプラインを稼働させ、無負荷ベースラインデータをロギングしている状態で、オペレーターが還流温度センサーRTD-102の信号ケーブルを物理的に抜線する（またはラック2のModbusイーサネットケーブルを抜線する）。
2. レコーダーはリアルタイムダッシュボードおよびエクスポートされるCSVファイルを監視する。
3. **適合の証明**：エクスポートデータは、1秒以内に直ちに `NaN`、`GAP`、または `DISCONNECTED` を記録し、品質ビットマスクは `0x0040`（センサー異常）へと遷移しなければならない。
4. **不適合の証明**：ダッシュボードやエクスポートデータが、タイムスタンプを進行させながら依然として 35.0°C を表示し続けた場合、そのパイプラインは陳腐化した古いデータを塗りつぶして出力している不正状態にある。試験は直ちに中止される。テレメトリパイプラインが死んだセンサーを誠実に死んだものとして報告できることが証明されるまで、加熱を行ってはならない。

## 記録すべき決定事項

速報のデータ取得セクションにおいて、以下を文書化すること：

- 確認されたModbusレジスタマップの改定番号、および検証された浮動小数点数バイト順序形式（CDAB／ワードスワップ付きビッグエンディアン）。
- 正確なポーリング間隔（1,000ms）および確認されたタイムアウト閾値（250ms）。
- MQTTブローカーのエンドポイント、トピック文字列、およびRetainedメッセージが無効化されていることの確認。
- 加熱前データ陳腐化プルーフテストの正式な実施記録。センサーが抜線された正確な秒、およびパイプラインが欠損ギャップを記録した秒を明記すること。
