영어판을 AI 보조로 번역한 것이다.

# 14. 텔레메트리 수집, Modbus-TCP 및 MQTT 파이프라인

플래시 보고서나 자동 생성된 차트의 정직성은 그 기입 칸을 채운 디지털 텔레메트리 파이프라인의 정직성에 정확히 비례한다.

현대의 메가와트급 데이터 센터 시험에서 텔레메트리는 데이터베이스 내부에 마법처럼 나타나지 않는다. 그것은 일련의 물리적 및 디지털 홉(hop)을 거친다: 접액부 침적 RTD 엘리먼트로부터, 로컬 아날로그-디지털 변환기(ADC)를 거쳐, 산업용 Modbus-TCP 필드버스를 가로지르고, 에지 수집기 게이트웨이를 통과하며, MQTT 메시지 브로커를 거쳐 불변의 시계열 저장소로 이어진다.

이 체인에서 단 하나의 홉이라도 조용히 고장 난다면—예를 들어 에지 폴러가 업데이트되지 않은 메모리 버퍼에 새로운 타임스탬프를 덧칠하거나, MQTT 브로커가 3일 전 발행된 캐시된 "보존(retained)" 메시지를 게시한다면—그 결과로 도출되는 플래시 보고서는 순전한 허구에 불과하다.

본 장은 데이터 무결성을 보장하는 데 필요한 정확한 Modbus 레지스터 구조, 바이트 순서 규약, 품질 비트마스크(Quality Bitmask) 아키텍처 및 MQTT 페이로드 스키마를 상세히 기술하며 각 홉의 기술 사양을 정의한다.

(엔드투엔드 텔레메트리 홉 아키텍처, IEEE-754 워드 스왑 함정, 16비트 품질 비트마스크 레지스터, 표준화된 JSON 페이로드 스키마는 그림 02 참조).

## 홉 1 및 2: 물리 센서에서 로컬 트랜스미터까지

여정은 물리적 프로세스 경계에서 시작된다:
- **온도**: 매니폴드 드롭의 중앙 코어 유동($1/3 \sim 1/2 D$)에 직접 삽입되고 45° 경사 서모웰 내부의 산화아연 열전도 컴파운드로 밀착된 4도선 Class A Pt100 RTD 엘리먼트.
- **체적 유량**: 작동 온도 대역 전반에 걸친 유체 점도 변화에 영향을 받지 않고 펄스 또는 고주파 디지털 주파수 출력을 제공하는 인라인 볼텍스(와류) 유량계.
- **차압**: 관벽에 수직으로 가공된 매끄럽고 연마된 정압 탭에 연결된 피에조 저항성 정압 트랜스미터.

트랜스미터에서는 고정밀 24비트 시그마-델타(Sigma-Delta) ADC가 1 kHz로 물리적 브리지를 샘플링하고, 로컬 디지털 이동평균 필터를 적용하여 초당 1회(**1 Hz**) 교정된 판독값을 출력한다.

## 홉 3: Modbus-TCP 필드버스 아키텍처

부하 장치 내부 컨트롤러는 표준 산업용 **Modbus-TCP (이더넷 포트 502)** 또는 Modbus-RTU (115,200 baud, 8-N-1로 작동하는 RS-485 직렬 버스)를 통해 작동 파라미터를 노출한다:

- **이산형 코일 (Discrete Coils, Function 0x01 / 0x05)**: 솔레노이드 밸브 위치(V-101 개방/폐쇄), 침적 히터 접촉기 피드백 상태, 비상 정지 회로 연속성, 누수 감지 로프 릴레이 상태 등의 이진 제어 상태.
- **입력 레지스터 (Input Registers, 30001+, Function 0x04)**: 로컬 하드웨어 ADC 채널에 의해 직접 생성된 읽기 전용 센서 측정값.
- **홀딩 레지스터 (Holding Registers, 40001+, Function 0x03 / 0x06 / 0x10)**: 지시된 부하 설정값, 작동 모드 구성, 경보 한계 임계값.

### IEEE-754 32비트 부동소수점 바이트 순서 함정
단일 16비트 Modbus 레지스터는 32비트 부동소수점 엔지니어링 수치(45.12°C와 같은 온도 판독값)를 저장할 수 없다. 부동소수점 값은 연속된 두 개의 16비트 레지스터(총 4바이트)를 필요로 한다.

마이크로컨트롤러 아키텍처마다 구현하는 워드 순서 규약이 다르다. 에지 게이트웨이가 잘못된 워드 순서를 가정하면 수치는 완전히 손상된다:
- **CDAB (Word Swap이 적용된 Big-Endian)**: Modbus 부동소수점의 산업 표준.
 - Reg 40001 = `0x4234`, Reg 40002 = `0x0000` $\implies$ 올바르게 **45.00°C**로 계산됨.
- **ABCD (Big-Endian Direct)**:
 - Reg 40001 = `0x0000`, Reg 40002 = `0x4234` $\implies$ **1.87 × 10^{-38}**(미세한 쓰레기 데이터!)로 계산됨.
- **BADC (Byte Swap이 적용된 Little-Endian)**: 완전히 다른 임의의 값으로 계산됨.

플래시 보고서의 작업 설정 시트에는 컨트롤러 펌웨어에서 사용하는 정확한 워드 순서 규약이 반드시 인용되어야 한다. 커미셔닝 중에 계절을 넘나들며 갑자기 온도가 튀는 것은 환경적 기적이 아니라 검증되지 않은 워드 스왑 파싱 오류다. 에지 게이트웨이 구성에서 파싱 방식을 수정하라. 유입되는 원시 16진수 바이트를 덮어쓰지 마라.

### 의무적인 16비트 품질 비트마스크 레지스터 (Reg 40050)
품질 플래그가 없는 원시 숫자는 검증되지 않은 주장에 불과하다. 부하 장치 컨트롤러는 내부 펌웨어 진단에 의해 실시간으로 업데이트되는 전용 **16비트 품질 비트마스크 레지스터(Quality Bitmask Register, 레지스터 40050)**를 유지해야 한다:

- **비트 0 (`0x0001`)**: `SUPPLY_TEMP_VALID` (1 = 정상, 0 = 결함/단선)
- **비트 1 (`0x0002`)**: `RETURN_TEMP_VALID` (1 = 정상, 0 = 결함/단선)
- **비트 2 (`0x0004`)**: `FLOW_METER_VALID` (1 = 정상, 0 = 결함/펄스 상실)
- **비트 4 (`0x0010`)**: `SENSOR_STALE_ALERT` (ADC가 3초를 초과하여 동일한 값을 반복할 때 설정)
- **비트 5 (`0x0020`)**: `COMM_TIMEOUT` (내부 트랜스미터 버스가 250ms를 초과하여 타임아웃될 때 설정)
- **비트 6 (`0x0040`)**: `OUT_OF_RANGE` (RTD 저항이 물리적 한계를 벗어날 때 설정)

레지스터 40050이 비트 4, 5 또는 6을 설정하는 경우, 에지 게이트웨이는 손상된 숫자를 다운스트림으로 발행하는 대신 해당 판독값을 즉시 **결함(FAULT)**으로 분류하고 결측 공백(gap)으로 기록해야 한다.

## 홉 4: 에지 게이트웨이 능동 폴링

에지 게이트웨이는 부하 장치 Modbus 컨트롤러를 쿼리하는 결정론적 1 Hz 폴링 루프를 실행한다:
- 폴러는 1,000밀리초마다 입력 및 품질 레지스터를 쿼리한다.
- **타임아웃 정책**: Modbus 슬레이브가 250밀리초 이내에 응답하지 못하면, 폴러는 해당 초에 대해 **통신 타임아웃(COMMUNICATION TIMEOUT)**을 기록한다.
- **전방 덧칠(Painting Forward)의 엄격한 금지**: 에지 게이트웨이가 마지막 성공 판독값을 캐싱하여 새로운 초의 타임스탬프를 덧칠해 찍는 행위는 엄격히 금지된다! 빈 칸을 방지하기 위해 이전 판독값을 전방으로 덧칠하는 것은 의도적인 데이터 날조다. 실패한 폴링은 `NaN` 또는 `MISSING`으로 기록되어야 한다. 연속 3회 폴링이 실패하면 해당 평탄 구간은 **무효(INVALID)**로 처리된다.

## 홉 5: MQTT 텔레메트리 브로커 및 JSON 스키마

에지 게이트웨이는 실시간 1초 텔레메트리를 패키징하여 로컬 MQTT 메시지 브로커에 발행한다:
- **토픽 계층 구조**: 자산 토폴로지에 부합하는 정갈한 계층 구조를 따라야 한다:
 `dc/[hall_id]/[rack_id]/telemetry` (예: `dc/hall-03/lb-01/telemetry`)
- **서비스 품질 (QoS)**: 네트워크 스위치의 일시적 결함으로 패킷이 손실되지 않도록 로컬 영구 버퍼링을 포함하는 **QoS 1 (At Least Once Delivery, 최소 1회 전달)**을 사용해야 한다.

### JSON 텔레메트리 스키마
브로커에 발행되는 모든 메시지는 타임스탬프, 전기, 수력, 품질 블록을 포함하는 표준화된 JSON 스키마를 준수해야 한다:

```json
{
 "timestamp": "2026-10-14T14:22:15.000Z",
 "rack_id": "LB-NVL72-01",
 "run_id": "RUN-2026-OCT-CX01",
 "commanded_kw": 120.0,
 "electrical": {
 "feeder_a_kw": 60.1,
 "feeder_b_kw": 59.9,
 "total_kw": 120.0,
 "voltage_v": 415.2,
 "current_a": 167.1,
 "pf": 0.999
 },
 "hydraulics": {
 "flow_lpm": 176.4,
 "supply_c": 35.08,
 "return_c": 45.12,
 "delta_t_k": 10.04,
 "dp_kpa": 112.5,
 "thermal_kw": 98.6
 },
 "companion_air": {
 "inlet_c": 24.2,
 "outlet_c": 38.5,
 "air_kw": 18.9
 },
 "quality": {
 "mask": "0x0007",
 "stale_flag": false,
 "raw_samples": 60
 }
}
```

### 금지해야 할 두 가지 치명적인 MQTT 습관
1. **보존 메시지(Retained Message)의 함정**: MQTT 프로토콜에서 발행자는 메시지를 "보존(retained)"으로 표시할 수 있으며, 이로 인해 브로커는 이를 저장하고 있다가 나중에 연결되는 모든 새로운 구독자에게 즉시 전달한다. 자동 플래시 보고서 스크립트가 브로커에 연결되어 보존된 메시지를 수집하게 되면, 공장 출하 시험 중 3일 전에 발행된 판독값을 가져오게 될 수 있다! 시험 계획서는 다음 사항을 반드시 의무화해야 한다: **모든 텔레메트리 발행자는 `retained = false`로 설정해야 한다**.
2. **유언(LWT, Last-Will-and-Testament) 메시지 오해석**: 브로커의 유언 메시지(에지 게이트웨이가 예기치 않게 연결 해제될 때 발행됨)는 명시적인 사망 페이로드(`{"status": "OFFLINE", "quality": "DEAD"}`)를 발행해야 한다. 보고 엔진은 이 페이로드를 즉각 인식하고 유지 시간 타이머를 정지시켜야 한다.

## 가열 전 정체 데이터 방지 증명 시험

시험 당일 열을 인가하기 전에 시험 팀은 **가열 전 정체 데이터 방지 증명 시험(Pre-Heat Stale Proof Test)**을 반드시 실행해야 한다:
1. 데이터 파이프라인이 가동되어 무부하 기준선 데이터를 로깅하고 있는 상태에서, 운전자가 반송 온도 센서 RTD-102의 신호 케이블을 물리적으로 분리한다(또는 캐비닛 2의 Modbus 이더넷 케이블을 뽑는다).
2. 기록자는 실시간 대시보드와 내보내기 중인 CSV 파일을 모니터링한다.
3. **적합성 입증**: 내보내기 파일은 1초 이내에 즉시 `NaN`, `GAP`, 또는 `DISCONNECTED`를 기록해야 하며, 품질 비트마스크는 `0x0040`(센서 결함)으로 전환되어야 한다.
4. **결함 입증**: 대시보드나 내보내기 파일이 계속 움직이는 타임스탬프와 함께 여전히 35.0°C를 표시하고 있다면, 해당 파이프라인은 정체 데이터를 전방 덧칠한 유죄이다. 시험은 즉시 중단된다. 텔레메트리 파이프라인이 고장 난 센서를 정직하게 보고할 수 있음을 입증할 때까지 열을 투입해서는 안 된다.

## 기록해야 할 결정 사항

플래시 보고서의 수집 섹션에 다음을 문서화하라:

- 확인된 Modbus 레지스터 맵 개정 번호 및 검증된 부동소수점 바이트 순서 형식(CDAB / Big-Endian Word Swap).
- 정확한 폴링 주기(1,000ms) 및 확인된 타임아웃 임계값(250ms).
- MQTT 브로커 엔드포인트, 토픽 문자열, 보존 메시지가 비활성화되었음을 확인한 사실.
- 센서가 분리된 정확한 초와 파이프라인이 공백(gap)을 등록한 초를 기록한 가열 전 정체 데이터 방지 증명 시험의 공인 실행 기록.
