영어판을 AI 보조로 번역한 것이다.

# 1. 주장

액랭 검증 프로젝트는 그것이 입증하도록 고용된 정확한 문장을 아무도 기록하지 않았을 때 첫 주에 이미 실패한다. "액랭 시스템이 잘 작동한다"는 것은 엔지니어링 주장이 아니다. 그것은 희망 섞인 소망에 불과하다. 감사 가능한 주장 문장은 물리적 플랜트 설비, 로드뱅크가 시뮬레이션하는 전기적 및 수력학적 부하 조건, 시설 1차측 냉각수(FWS) 공급 경계 조건, 그리고 시험 문서 팩이 인도되었을 때 시설 소유주(발주자)가 내릴 정확한 상업적 결정을 명시한다.

이 현장 지침서의 모태가 된 AI 데이터 전산실 프로젝트들에서 그 상업적 결정은 시설 냉각 인프라가 IT 장비 배치를 위해 법적·기계적으로 수용 가능한 상태인지 여부였다. 가속 컴퓨팅 칩이 분산 모델 훈련 워크로드를 성공적으로 실행할 수 있는가가 아니었다. 시제품 액체 로드뱅크가 제조 R&D 표준을 충족했는가가 아니었다. 그러한 주장들은 다른 엔지니어링 업무 범위, 다른 테스트 벤치, 다른 서명권자의 몫이다.

```
+----------------------------------------------------------------------------------------------------+
| 주장 문장의 경계 조건 (BOUNDARY) |
+------------------------------------+---------------------------------------------------------------+
| 주장이 법적으로 입증하는 것 | 주장이 입증할 수 없는 것 |
+------------------------------------+---------------------------------------------------------------+
| • 1.2 MW 정격에서의 CDU 열전달 성능| • 실리콘 연산 효율 또는 텐서 연산 성능 |
| • 2차측 펌프 N+1 절체 속도 | • 퀵 디스커넥트(QD)의 장기 갈바닉 부식률 |
| • 매니폴드 역환수(reverse-return) 균형 | • 시설 중앙 칠러 플랜트의 계절별 프리쿨링 PUE |
| • 엔탈피 열 폐합비 >= 97.0% | • 시제품 로드뱅크 히터 발열체의 제조 내구성 |
| • 2N 전기 피드 절체 시 과도 연속성 | • 시설 건물 외피의 구조적 풍하중 규격 적합성 |
+------------------------------------+---------------------------------------------------------------+
```

## 프로젝트 주장 문장의 수립

로드뱅크 대수를 세기 전에 주장 문장부터 작성해라. 필요한 장비 대수와 전기적 토폴로지는 문장의 결과물이지 원인이 아니다. 만약 주장이 10개의 120 kW 랙 설치 공간에 냉각액을 공급하는 단 한 대의 1.2 MW 인라인 냉각액 분배 장치(CDU)로 한정되어 있다면, 원청 시공사가 한 달 동안 40대를 임대했다는 이유만으로 전체 행에 40대의 로드뱅크를 배치해서는 안 된다. 만약 주장이 화이트 스페이스(white space) 전체 외피—액체 콜드플레이트에서 빠져나간 잔여 15%~20%의 대류 공기 부하를 포집하는 전산실 공조기(CRAH) 또는 팬월(fan wall)을 포함—를 포괄한다면, 공기측 열 경계 조건을 주장 문장에 명시적으로 규정해야 한다. 그렇지 않으면 시험은 구조적으로 무효가 된다.

시설 전체 커미셔닝에서 발주자 프로젝트 요구조건(OPR, Owner's Project Requirements)은 방대한 계약 문서이다. 시설 구조와 기계 배관이 이미 설치 완료된 이후에 착수되는 액랭 검증 작업에서는, 동일한 거버넌스를 구속력 있는 단 한 페이지로 압축해 내야 한다:
1. 양산 서버의 입고가 승인되기 전에 어떤 운전 지표가 입증되어야 하는가?
2. 어느 물리적 시스템이 검증 경계 내부에 포함되는가?
3. 어느 플랜트 시스템이 명시적으로 제외되는가?

발주자가 이미 승인된 OPR 페이지를 보유하고 있다면, 전산실 바닥의 물리적 배관과 대조하여 감사해라. 현장 시험 스크립트의 여백에 조용히 임의 수정해 넣지 마라. 만약 발주자에게 이 문서가 없다면, 단 한 개의 공구도 포장을 뜯기 전에 엔지니어가 작성하여 잉크로 서명을 받아내야 하는 필수 선행 문서가 바로 이 1페이지짜리 주장 문서이다. 서명되지 않은 주장은 최종 완료 회의를 시험 수행 주체가 무엇을 입증하도록 대가를 지급받았는가를 두고 벌이는 진흙탕 싸움으로 전락시킨다.

## 설계 기준(BOD)의 현장 감사

설계 기준(BOD, Basis of Design)은 동반 문서이다. 이는 발주자의 주장을 충족하기 위해 의도된 엔지니어링 가정, 열전달 계수, 제어 로직을 명확히 서술한다. 엔지니어는 BOD를 초기 설계 도면이 아니라 현장에 서 있는 그대로의 물리적 데이터 전산실과 대조하여 감사해야 한다.

도면과 실제 시공 사이의 차이를 결코 어물쩍 평균 내지 마라. 만약 BOD가 프로필렌 글리콜 25% 수용액(PG25)을 순환시키는 DN150 역환수(reverse-return) 2차측 헤더를 규정하고 있는데, 준공된 현장 배관은 부식 억제제가 첨가된 탈염수가 채워진 DN100 직접 환수(direct-return) 매니폴드라면, 그 불일치는 허용 가능한 "현장 조정"이 아니다. 그것은 누군가 펌프 특성 곡선을 그리거나 시스템이 "규격에 적합하다"고 선언하기 전에 반드시 주장 표지에 기록되어야 할 중대한 설계 편차이다.

검증이 입증할 수 없는 한계는 입증하는 내용과 반드시 동일한 페이지에 나란히 기재되어야 한다. 검증 시험은 서버 제조업체의 보증을 인증하지 않는다. 액체 로드뱅크 자체를 승인하지도 않는다. 로드뱅크의 장비 승인은 Book 01의 공장 프로토콜에 따라 이미 이루어졌어야 하며, 그렇지 못했다 하더라도 본 검증 시험이 현장 커미셔닝이라는 미명 하에 슬그머니 공장 인수 시험(FAT)을 대신 수행해 주지는 않는다. 인증되지 않은 퀵 디스커넥트(QD) 커플링, 검증되지 않은 살균 화학 약품, 또는 프로젝트 시방서가 정량화하지 못한 최소 유량 하한선(flow floor)을 검증해 주지도 않는다. 그러한 데이터 셀들은 시험 스크립트가 준거 문서를 인용할 때까지 빈칸으로 유지된다. 빈칸은 의도적인 작업 정지이다. 기억에 의존해 채워 넣은 검증되지 않은 숫자는 데이터로 둔갑한 결함일 뿐이다.

마지막으로, 주장은 전산실의 운전 상태를 명확히 규정한다:
- **빈 전산실 검증(Empty Hall Verification)**: 전산실 내에 양산 IT 하드웨어나 활선 네트워크 패브릭이 전혀 가전(energize)되지 않은 상태에서 수행.
- **유지보수 정전 기간(Maintenance Outage Window)**: 계획된 시설 셧다운 기간 동안 격리된 루프에서 수행.
- **가동 중 전산실 인접 검증(Live Hall Proximity)**: 인접한 행(row)들이 실제 양산 워크로드를 처리하고 있는 공유 기계 플랜트에서 수행.

활선 시설에 대해 명시적인 위험 완화 조치 없이 빈 전산실용으로 작성된 시공 방법서를 적용하는 것은 고객 서비스 중단을 유발할 무단 사고를 자초하는 행위이다. 시설이 가동 중이라면, 현장의 표준 운영 절차(SOP)와 작업 절차서(MOP) 프로토콜이 이 책의 내용보다 우선하며, 해당 문서 번호들이 주장 시트의 최상단에 기재되어야 한다.

## 시험 시작 전 기록해야 할 결정 사항

- 발주자 측 공인 기술사(PE)와 커미셔닝 리드(Cx Lead)가 연대 서명한 프로젝트 주장 문장.
- 작업 범위 내에 포함된 물리적 장비 목록 및 명시적으로 제외된 플랜트 설비 목록.
- 기록된 모든 물리적 편차를 포함하여 감사된 특정 설계 기준(BOD) 개정판 번호.
- 검증된 시험 문서 팩을 바탕으로 발주자가 내릴 구체적인 상업적 결정.
- 시설의 운전 상태(빈 전산실, 계획된 정전, 또는 가동 중인 전산실 규칙 적용 여부).
