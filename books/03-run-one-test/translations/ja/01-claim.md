# 1. 主張の一文

液冷検証プロジェクトは、自らが証明するために雇われた厳密な「主張の一文」を誰も書き留めないとき、着任第1週にして失敗する。「液冷設備が正常に動作する」というのは工学的な主張ではなく、単なる希望的観測にすぎない。監査に耐えうる主張の一文とは、対象となる物理プラント、負荷装置が模擬する電気的・水力学的負荷条件、施設側冷却水（一次側）の境界条件、そして試験受入パックが返送された際に施設所有者が下す厳密な商業的・法的判断を具体的に明記したものである。

本フィールドガイドの基盤となったAIデータホールプロジェクトにおいて、その商業的判断とは「施設冷却インフラが本番IT機器の展開を受け入れるにあたり、法規的および機械工学的に合格であるか否か」であった。アクセラレータ計算チップが分散モデル学習ワークロードを完走できるか否かではない。試作液冷負荷装置が製造R&D基準を満たしているか否かでもない。それらの主張は、他の工学領域、他の試験ベンチ、そして他の署名権限に属するものである。

```
+----------------------------------------------------------------------------------------------------+
| 主張の一文が規定する境界 |
+------------------------------------+---------------------------------------------------------------+
| 主張が法的に証明するもの | 主張が証明できない（証明してはならない）もの |
+------------------------------------+---------------------------------------------------------------+
| • 1.2 MW定格におけるCDUの熱交換能力| • 半導体の演算効率やテンソル計算性能 |
| • 二次側ポンプのN+1切替速度 | • クイック継手の長期的な電食・ガルバニック腐食速度 |
| • マニホールドの逆還水水力バランス | • 施設中央熱源（チラー）の季節フリークーリングPUE |
| • エンタルピー熱バランス閉合 >= 97%| • 試作負荷装置のヒータエレメント製造耐久性 |
| • 2N電源系統の受電切替乗り切り | • 施設建屋構造の外装耐風圧適合性 |
+------------------------------------+---------------------------------------------------------------+
```

## プロジェクト主張の策定

負荷装置の台数を数える前に、この一文を起草しなければならない。必要な装置台数や電気トポロジーは一文から導かれる結果であって、出発点ではない。主張の対象が、10台の120 kWラックフットプリントへ冷却液を供給する単一の1.2 MWインロー型冷却液分配装置（CDU）に限定されている場合、元請業者が月極でレンタルしたからといって、列全体に40台の負荷装置を並べてはならない。主張の対象がホワイトスペース空間全体を含み、液冷コールドプレートから漏れた15%〜20%の残留対流熱負荷を捕捉するCRAH空調機やファンウォールまで包含する場合、空気側の熱境界も主張の一文に明記しなければならない。さもなければ、試験構造自体が無効となる。

施設全体の包括的コミッショニングにおいて、発注者要件書（OPR: Owner's Project Requirements）は膨大な契約図書となる。しかし、建屋構造と機械配管がすでに完成した後に着手する液冷検証においては、そのガバナンスを単一の拘束力ある1ページに凝縮する必要がある：
1. 本番サーバの納入が許可される前に、どのような運用指標を実証しなければならないか。
2. どの物理システムが検証境界の内部に含まれるか。
3. どのプラントシステムが明示的に適用除外されるか。

所有者がすでに承認済みのOPRシートを保持している場合、現場の物理配管と突き合わせて監査すること。現場試験スクリプトの余白で無断修正してはならない。所有者がこの文書を欠いている場合、工具を1つ開梱する前にインクで起草し署名を取り付けるべき前提文書が、この1ページの主張書である。署名のない主張書は、最終完了会議において「試験担当者は何を証明するために報酬を支払われたのか」という紛糾を招くことを保証する。

## 設計基準（BOD）の監査

設計基準書（BOD: Basis of Design）はその対となる文書である。所有者の主張を満たすために意図された工学的仮定、熱通過率、および制御ロジックを体系化している。BODの監査は、初期設計図面ではなく、現場に実在する物理データホールに対して実施しなければならない。

図面と実施工の差異を勝手に平均化して妥協してはならない。BODがプロピレングリコール25%水溶液（PG25）を用いたDN150の逆還水（リバースリターン）二次側ヘッダーを規定しているのに対し、竣工状態が脱塩水と防食剤を充填したDN100の直接還水（ダイレクトリターン）マニホールドである場合、その差異は許容される「現場調整」ではない。何者かがポンプ特性曲線をプロットしたり設備を「適合」と宣言したりする前に、主張書の表紙に記録されるべき重大な設計逸脱である。

検証が証明できない項目は、証明できる項目と同一ページに明記しなければならない。サーバメーカーの製品保証を認証するものではない。液冷負荷装置そのものを受入検査するものでもない。その受入は第1巻の工場試験手順書のもとで完了しているか、あるいは未完了であり、現場コミッショニングを装って工場受入試験を密かに肩代わりしてはならない。認証されていないクイック継手、未検証の殺菌剤化学組成、またはプロジェクト仕様書が定量化を怠った最低流量下限を妥当化するものでもない。試験スクリプトが準拠文書を引用するまで、それらのデータセルは空欄のままでなければならない。空欄のセルは意図的な停止を意味する。記憶に頼って転記された未検証の数値は、データに偽装された欠陥である。

最後に、主張書はデータホールの運用状態を明確に規定する：
- **空ホール検証（Empty Hall Verification）**: 本番IT機器や稼働ネットワーク機器が通電される前の空間で実施される。
- **保守停止ウィンドウ（Maintenance Outage Window）**: 施設の計画停止期間中、隔離されたループ上で実施される。
- **稼働ホール近接（Live Hall Proximity）**: 隣接するラック列が本番ワークロードを冷却している共有機械プラント上で実施される。

空のデータホール向けに書かれた作業要領書を、明示的なリスク緩和措置なしに稼働中の施設に適用することは、重大な顧客障害を引き起こす無承認の事故予備軍である。施設が稼働中である場合、現場の標準作業手順書（SOP）および作業実施要領書（MOP）のプロトコルが本書に優先し、その準拠文書番号を主張シートの冒頭に掲げなければならない。

## 試験開始前に記録すべき決定事項

- 発注者主任技術者（Owner PE）およびコミッショニング責任者（Cx Lead）が連名でインク署名したプロジェクト主張の一文。
- スコープ内に含まれる物理機器一覧、および明示的に除外されるプラント一覧。
- 監査された特定の設計基準（BOD）改定番号、および記録されたすべての物理的施工逸脱。
- 検証済みテストパックに基づいて所有者が下す具体的な商業的判断。
- 施設の運用状態（空ホール、計画停止、または稼働中データホール規則の適用）。
