# 2. สิบสองผลิตภัณฑ์ ตามลำดับ

การทำคอมมิชชันนิง (commissioning) ระดับมืออาชีพไม่ได้เริ่มต้นด้วยพลังงานความร้อน แต่เริ่มต้นด้วยลำดับที่เข้มงวดของผลงานส่งมอบทางวิศวกรรมสิบสองรายการ หากคุณข้ามผลิตภัณฑ์รายการใดรายการหนึ่งในลำดับชั้นนี้ ลายมือชื่อทุกตัวที่ลงนามหลังจากนั้นจะกลายเป็นการรับรองงานที่ไม่เคยได้รับการบันทึกเป็นลายลักษณ์อักษรตามกฎหมายหรือไม่เคยได้รับการตรวจสอบเป็นพยานทางกายภาพเลย

ผลิตภัณฑ์ทั้งสิบสองรายการนี้ประกอบกันเป็นลำดับขั้นของความรับผิดชอบ ไม่ใช่ตารางปฏิทินการบริหารโครงการ ในโถงศูนย์ข้อมูลเดิมที่การก่อสร้างทางกายภาพเสร็จสิ้นไปแล้ว ผลิตภัณฑ์บางรายการอาจเป็นเอกสารที่คุณต้องนำมาตรวจสอบและแนบเพิ่มเติม แทนที่จะเป็นกิจกรรมที่คุณต้องลงมือทำใหม่ตั้งแต่ต้น อย่างไรก็ตาม ห้ามละเว้นผลิตภัณฑ์รายการใดรายการหนึ่งในสิบสองรายการนี้ด้วยความเงียบเฉยเป็นอันขาด

**สิบสองผลิตภัณฑ์คอมมิชชันนิงตามลำดับ**

| 01 | ข้อกำหนดโครงการของเจ้าของ (OPR) | ประโยคข้อกล่าวอ้างที่ตรวจสอบได้และขอบเขตการปฏิบัติงาน |
| :--- | :--- | :--- |
| 02 | เกณฑ์พื้นฐานการออกแบบ (BOD) | แผนที่นำทางของวิศวกรผู้ออกแบบเพื่อตอบสนอง OPR |
| 03 | การอนุมัติ OPR และ BOD | เกณฑ์ฐานร่วมกันที่ลงนามก่อนเริ่มร่างสคริปต์การทดสอบ |
| 04 | บันทึกการทบทวนการออกแบบ | บันทึกการตรวจสอบการออกแบบอย่างเป็นทางการหรือหนังสือยกเว้น |
| 05 | แผนงานคอมมิชชันนิง (Cx Plan) | ขอบเขต กำหนดการ เกต โปรโตคอล และการกำกับดูแลทีมงาน |
| 06 | การตรวจสอบข้อกำหนดสัญญา | เมทริกซ์การตรวจสอบย้อนกลับของข้อกำหนดการทดสอบในสัญญา |
| 07 | รายการตรวจงานก่อสร้าง (PFC) | การทวนสอบ QA/QC สภาวะสถิต ปราศจากพลังงาน ก่อนใช้งาน |
| 08 | ขั้นตอนการทดสอบการทำงาน (FPT) | สคริปต์การปฏิบัติการแบบพลวัตทีละขั้นตอนที่ได้รับอนุมัติ |
| 09 | บันทึกการทวนสอบและร่วมเป็นพยาน | บันทึกและแผ่นข้อมูลภาคสนามที่มีบุคคลภายนอกร่วมเป็นพยาน |
| 10 | ทะเบียนบันทึกประเด็น / พันช์ลิสต์ | ทะเบียนติดตามข้อบกพร่อง ผู้รับผิดชอบ และการทดสอบซ้ำ |
| 11 | รายงานคอมมิชชันนิงตามรอบเวลา | บันทึกกะประจำวันและบทสรุปผู้บริหารประจำสัปดาห์ |
| 12 | คู่มือระบบและรายงาน Cx ฉบับสมบูรณ์ | ฐานข้อมูลการทำงานตามสภาพทดสอบจริงและชุดเอกสารส่งมอบงาน |

## รายละเอียดของผลิตภัณฑ์แต่ละรายการ

### 01. ข้อกำหนดโครงการของเจ้าของ (Owner's Project Requirements - OPR)
นี่คือข้อกล่าวอ้างที่ตรวจสอบได้ตามที่นิยามไว้ในบทที่ 1 ซึ่งระบุค่าตัวชี้วัดอุณหภูมิ อัตราการไหล ความหนาแน่นของกำลังไฟฟ้า และระดับความซ้ำซ้อน (redundancy) ไว้อย่างชัดเจนเพื่อใช้ในการตรวจรับรองความพร้อมใช้งานของระบบ IT

### 02. เกณฑ์พื้นฐานการออกแบบ (Basis of Design - BOD)
เอกสารที่จัดทำขึ้นโดยวิศวกรวิชาชีพผู้ออกแบบระบบกลศาสตร์ ไฟฟ้า และสุขาภิบาล (MEP) ซึ่งอธิบายว่าอุปกรณ์ของอาคาร ขนาดเส้นผ่านศูนย์กลางท่อ ลูปควบคุม และปั๊มต่างๆ บรรลุตามข้อกำหนด OPR ได้อย่างไร ในงานทวนสอบหน้างาน คุณต้องขอรับเอกสารฉบับแก้ไขตามแบบก่อสร้างจริง (as-built) ล่าสุด คุณต้องไม่เขียน BOD แข่งขันขึ้นมาเองในรายงานการทดสอบภาคสนาม

### 03. การทบทวนและอนุมัติ OPR และ BOD
การลงนามอย่างเป็นทางการโดยผู้มีส่วนได้ส่วนเสียหลัก ได้แก่ เจ้าของโครงการ ผู้รับเหมาหลัก และหน่วยงานกำกับดูแลการทำคอมมิชชันนิง (Commissioning Authority - CxA) ข้อกำหนดที่ไม่ได้รับการอนุมัติเป็นเพียงร่างแบบร่างหนึ่งเท่านั้น การทดสอบที่ดำเนินการเทียบกับร่างที่ไม่ได้รับอนุมัติอาจถูกปฏิเสธเมื่อเจ้าของโครงการเปลี่ยนชุดผู้บริหาร ซึ่งจะนำไปสู่ความสูญเสียค่าใช้จ่ายมหาศาลในการระดมพลทดสอบใหม่

### 04. บันทึกการทบทวนการออกแบบ (Design Review Record)
การตรวจสอบทางเอกสารของแบบแปลนชลศาสตร์และไฟฟ้าเทียบกับแนวทางปฏิบัติทางอุตสาหกรรม (เช่น มาตรฐาน ASHRAE Technical Committee 9.9 และ Open Compute Project) หากสัญญาของคุณเริ่มต้นหลังจากที่อาคารสร้างเสร็จแล้ว ผลิตภัณฑ์นี้จะต้องเป็นการทวนสอบทางเอกสารของการทบทวนการออกแบบในอดีต หรือเป็นหนังสือแถลงการณ์ที่ลงนามโดยเจ้าของโครงการซึ่งระบุอย่างชัดเจนว่าการตรวจสอบการออกแบบอยู่นอกเหนือขอบเขตงานของคุณ ห้ามเว้นว่างไว้ในดัชนีปิดเล่มรายงานเป็นอันขาด

### 05. แผนงานคอมมิชชันนิง (Commissioning Plan - Cx Plan)
เอกสารการกำกับดูแลหลักที่กำหนดขอบเขตการทดสอบ การจัดสรรทรัพยากร โปรโตคอลการร่วมเป็นพยาน เมทริกซ์การสื่อสาร และกฎเกณฑ์การผ่านเกต แผนภูมิแกนต์ (Gantt chart) ไม่ใช่แผนงานคอมมิชชันนิง แผนภูมิแกนต์เป็นเพียงภาพจำลองเส้นเวลาเท่านั้น แต่ Cx Plan จะต้องอธิบายเกตทางเทคนิค เกณฑ์การสั่งหยุด และโครงสร้างการจัดการเอกสาร

### 06. ข้อกำหนดคอมมิชชันนิงในเอกสารสัญญา
การตรวจสอบข้อกำหนดการทดสอบที่ระบุไว้ในข้อกำหนดสัญญาของงานกลศาสตร์และไฟฟ้า (เช่น CSI Division 23 สำหรับระบบ HVAC และ Division 26 สำหรับระบบไฟฟ้า) ในอาคารที่สร้างเสร็จแล้ว คุณไม่สามารถแก้ไขสัญญาเดิมได้ สิ่งที่คุณต้องทำคือจัดทำเมทริกซ์ที่ระบุว่าคุณกำลังทวนสอบเทียบกับข้อกำหนดการทดสอบใด และข้อกำหนดใดที่ไม่สามารถดำเนินการได้เนื่องจากข้อมูลในอดีตสูญหาย

### 07. รายการตรวจงานก่อสร้าง (Pre-Functional Checklists - PFC)
แผ่นบันทึกการทวนสอบทางกายภาพในสภาวะสถิต ซึ่งดำเนินการในขณะที่ระบบวิศวกรรมอาคารถูกตัดกระแสไฟฟ้าโดยสมบูรณ์ เอกสารนี้ใช้ทวนสอบป้ายรหัสอุปกรณ์ การจัดตำแหน่งแนวแกนทางกายภาพ สภาพการเปิดหีบห่อ รอยมาร์กแรงบิด (torque mark) บนขั้วต่อทางไฟฟ้า การทดสอบคงแรงดันไฮโดรสแตติกของระบบท่อ และการชะล้างทำความสะอาดระบบ การเดินตรวจหน้างานโดยไม่มีแผ่นรายการตรวจสอบที่พิมพ์ไว้ล่วงหน้าถือเป็นเพียงการเดินเล่นอย่างไม่เป็นทางการ

### 08. ขั้นตอนการทดสอบการทำงาน (Functional Test Procedures - FPT)
สคริปต์การทดสอบทีละขั้นตอนที่ได้รับการอนุมัติ ซึ่งควบคุมทุกลำดับการทำงานแบบพลวัต แต่ละขั้นตอนต้องระบุสภาวะเริ่มต้น คำสั่งปฏิบัติการที่แน่นอน ระดับความแม่นยำของเครื่องมือวัด ช่วงตัวเลขที่ยอมรับได้ และเกณฑ์การสั่งหยุดที่ชัดเจน สคริปต์ที่เขียนขึ้นหน้างานในเช้าวันทดสอบถือเป็นแบบร่างที่ยอมรับไม่ได้ เพราะ "ผลลัพธ์ที่คาดหวัง" ย่อมจะถูกเขียนล้อตามสิ่งที่ระบบกลศาสตร์บังเอิญทำได้ไปโดยปริยาย

### 09. บันทึกการทวนสอบและร่วมเป็นพยาน (Verification and Witness Records)
การลงมือปฏิบัติจริงตามสคริปต์ที่ได้รับอนุมัติ การเป็นพยานและการปฏิบัติการเป็นหน้าที่ทางกฎหมายที่แยกจากกัน ช่างเทคนิคที่ทำหน้าที่หมุนวาล์วควบคุมและสับคันโยกเบรกเกอร์ไม่สามารถทำหน้าที่เป็นพยานเพียงคนเดียวในการตรวจรับรายการนั้นได้ เมื่อบุคคลคนเดียวทำหน้าที่ทั้งสองอย่าง อคติที่เกิดขึ้นโดยไม่รู้ตัวย่อมบิดเบือนข้อมูลอย่างหลีกเลี่ยงไม่ได้

### 10. ทะเบียนบันทึกประเด็น / รายการแก้ไข (Issues Log / Punch List Register)
ระบบติดตามที่บันทึกข้อบกพร่อง ความเบี่ยงเบน รอยรั่วไหล ข้อผิดพลาดของเซ็นเซอร์ และการแกว่งตัวของระบบควบคุมทุกรายการ แต่ละรายการต้องระบุวันที่ ขั้นตอนในสคริปต์ ระดับความรุนแรง ผู้รับเหมาที่รับผิดชอบ การแก้ไขที่จำเป็น และเกณฑ์การยอมรับในการทดสอบซ้ำ ข้อบกพร่องที่พูดคุยกันเฉพาะในการสนทนาด้วยวาจาหรือในแอปส่งข้อความถือว่าไม่มีตัวตนอยู่จริงตามกฎหมาย

### 11. รายงานคอมมิชชันนิงตามรอบเวลา
บันทึกสรุปประจำกะที่ส่งมอบเมื่อสิ้นสุดหน้าต่างการทำงานแต่ละกะ และรายงานสรุปประจำสัปดาห์ที่ส่งถึงผู้บริหาร รูปแบบการรายงานต้องได้รับการตกลงกันตั้งแต่การประชุมเปิดโครงการ ซึ่งรวมถึงรูปแบบรายงานสำหรับวันที่การทดสอบถูกสั่งหยุดด้วย วันที่ไม่มีรายงานประจำกะถือเป็นความล้มเหลวในการควบคุมโครงการ

### 12. คู่มือระบบและรายงานคอมมิชชันนิงฉบับสมบูรณ์
ชุดเอกสารส่งมอบงานฉบับสมบูรณ์ ประกอบด้วยแผ่นบันทึกหลักที่มีลายมือชื่อรับรองครบถ้วน ใบรับรองการสอบเทียบเครื่องมือวัด ไฟล์ข้อมูลอนุกรมเวลาดิบ บันทึกแนวโน้มจากระบบ BMS รายการแก้ไขที่ปิดข้อบกพร่องเรียบร้อยแล้ว และแนวทางการปฏิบัติงานที่วิศวกรประจำอาคารต้องใช้เพื่อควบคุมระบบให้อยู่ในขอบเขตที่ผ่านการทวนสอบแล้ว

ห้ามเปลี่ยนหมายเลขหรือรวมผลิตภัณฑ์ทั้งสิบสองรายการนี้เข้าด้วยกันเพียงเพื่ออำนวยความสะดวกแก่ความเคยชินของผู้รับเหมาในพื้นที่ หากผลิตภัณฑ์ใดถูกยกเว้นตามสัญญา แผนงานคอมมิชชันนิงจะต้องระบุข้อยกเว้นนั้นไว้อย่างชัดเจน และรายงานฉบับสมบูรณ์จะต้องยืนยันข้อยกเว้นนั้นอีกครั้ง ความถูกต้องตามข้อกำหนดทางวิชาชีพถูกรักษาไว้ด้วยการระบุขอบเขตเป็นลายลักษณ์อักษร ไม่ใช่ด้วยความเงียบเฉย

## การตัดสินใจที่ต้องบันทึกก่อนเริ่มการทดสอบ

- ผลิตภัณฑ์ทั้งสิบสองรายการจำแนกออกเป็น: รายการที่ต้องจัดทำขึ้นใหม่, รายการที่ต้องนำมาจากงานก่อนหน้าเพื่อแนบเพิ่มเติม, หรือรายการที่ยกเว้นเป็นลายลักษณ์อักษรพร้อมลายมือชื่อ
- ข้อกำหนดการตั้งรหัสเอกสารและนโยบายการควบคุมฉบับแก้ไข (revision control) ที่ได้รับอนุมัติ
- แหล่งจัดเก็บเอกสารและสิทธิ์ความปลอดภัยในการเข้าถึงทะเบียนรายการแก้ไขหลัก (Master Issues Log)
- รายชื่อผู้รับเอกสารและกำหนดเวลาส่งมอบบันทึกสรุปประจำกะ
